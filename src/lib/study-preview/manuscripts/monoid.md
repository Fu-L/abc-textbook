区間の答えを高速に求めるには、まず「隣り合う二つの区間について、何を覚えていれば全体の答えを作れるか」を決める。**データ構造を選ぶ前に、要約する値と結合規則を設計する**単元である。

## 考え方

文字列の区間内で、同じ文字が連続する長さの最大値を求めたい。左区間も右区間も答えが2でも、連結後の答えが2のままとは限らない。`aa`
と `aa` を合わせれば4になる。答えだけでは、境界をまたぐ連続部分を復元できない。

そこで、各区間について次の六つを覚える。

| 要約                  | 意味                               |
| --------------------- | ---------------------------------- |
| `len`                 | 区間の長さ                         |
| `leftVal`, `rightVal` | 両端の文字                         |
| `pref`, `suff`        | 左端・右端から同じ文字が続く長さ   |
| `best`                | 区間内で同じ文字が続く長さの最大値 |

左区間を $$A$$、右区間を $$B$$ とする。両区間が空でないとき、境界の文字が違えば全体の `best`
は左右の `best` の最大値。等しければ、境界をまたぐ $$A.\mathrm{suff}+B.\mathrm{pref}$$
も候補になる。例えば `baa` と `aab` は境界でつながり、`best` が2から4になる。

全体の `pref`
が右区間へ伸びるのは、境界の文字が等しく、かつ左区間の全体が同じ文字のときだけ。その場合は
$$A.\mathrm{len}+B.\mathrm{pref}$$、それ以外は $$A.\mathrm{pref}$$。`suff`
も左右を入れ替えて求める。長さは和、両端の文字は外側の文字を引き継ぐ。

## 成立条件と計算量

要素一つの要約は `len=pref=suff=best=1`。空区間は `len=0`
とし、結合すると相手の要約をそのまま返す。これが単位元であり、空区間の端の文字を比較する必要はない。

この結合は、実際に二つの文字列を連結した結果の要約を正しく作る。三つの文字列をどちらの順序で括っても同じ文字列になるため、要約の結合にも結合則が成り立つ。結合的な演算と単位元を持つ仕組みをmonoidという。左右の順序を入れ替えられるとは限らず、Segment
Treeでも取得した区間を元の順序で結合する。

この例の要約サイズ・結合費用は定数なので、Segment Treeの構築は $$O(N)$$、一点更新と区間取得は各
$$O(\log N)$$、空間は $$O(N)$$。一般に要約サイズを $$s$$、結合費用を $$T$$ とすると、構築は
$$O(NT)$$、操作は $$O(T\log N)$$、空間は $$O(Ns)$$ になる。

復習では、**答えだけで結合できない反例、境界に必要な情報、単位元、結合則の根拠**を言葉にする。基本操作は[概念上の親単元](/learn/query/monoid-segment-tree/)へ。下の主配置問題から進み、関連問題は他の主題との組合せを確認するときに使う。
