# backtracking・可逆な探索状態

習得対象の目安: **緑色（800–1199）**。再帰と訪問済み管理を使い、選択と取り消しが対応する探索を実装する。

対象色の読み方は[本書の読み方](/learn/modeling/)を参照してください。

概念上の親: [モデル変換とアルゴリズム設計](/learn/modeling/)。問題へ進む前に、下記の直接前提のうち未習得の単元を確認する。

## 概要

選択を一つ加えて次の可能性を調べ、戻るときにその選択を取り消す。この往復で、互いに干渉させずに多数の候補を調べる方法がbacktrackingである。

中心になるのは再帰の構文ではなく、「今の選択だけを状態へ反映する」という不変条件である。何を保存し、いつ変更し、どう元へ戻すかを一組で設計する。

### 習得する技能

- 再帰の前後で使用状態を対称に更新・復元し、現在pathだけの制約を保って探索木を漏れなく列挙できる。

## 考え方

### 頂点へ一度着いたことと、今の経路で使っていることは違う

無向グラフで辺 `s–a, s–b, a–c, b–c` があるとする。始点 `s` から、同じ頂点を二度使わない経路を列挙したい。

まず `s → a → c` と進み、戻ってから `s → b` を調べると、今度は `c` へ進める。前の探索で `c` へ着いたことがあっても、現在の経路 `s → b` ではまだ使っていないためである。通常の到達可能性のDFSのように `c` を永久に訪問済みにすると、後者を失う。

ここでは `used[v]` を「現在の経路に頂点 $$v$$ が含まれる」と定義する。`s → a → c` を調べ終えて `c` から戻るときは `used[c]` をfalseへ戻す。さらに `a` から戻るときは `used[a]` も戻す。これにより `s → b → c` を独立に調べられる。

| 場面 | 現在の経路 | trueである頂点 |
| --- | --- | --- |
| `a` 側の枝を調べる | `s, a, c` | `s, a, c` |
| `c` から戻る | `s, a` | `s, a` |
| `a` から戻る | `s` | `s` |
| `b` 側へ進む | `s, b, c` | `s, b, c` |

### 関数の入口と出口で、約束をそろえる

次は単純経路を、頂点列として一つずつ扱う擬似コードである。`process` は現在の経路を一候補として数えるなどの処理を表す。

```text
search(v):
    used[v] = true
    path.push(v)
    process(path)
    for each neighbor u of v:
        if not used[u]:
            search(u)
    path.pop()
    used[v] = false
```

呼出し直前には、`used` と `path` は親までの経路を表す。入口で `v` を追加し、子を一つ調べるたびにその子が状態を元へ戻すので、次の子は同じ親状態から開始できる。出口で自分の変更も取り消す。この約束を帰納的に使うと、兄弟の探索が干渉しないことを示せる。

既に経路内にある頂点へ進まないため、生成する経路は必ず単純である。逆に、任意の合法な経路の次の頂点は未使用なので、その延長は必ず試される。単純グラフでは同じ頂点列を作る分岐列も一つに定まるため、重複しない。平行辺がある場合には、頂点列を数えるか辺列を数えるかで重複の扱いが変わる。

### 状態を丸ごとコピーするか、差分を取り消すか

各分岐へ状態のコピーを渡す方法でも、枝どうしを独立にできる。しかし経路が長いと、呼出しごとに大きい集合や配列をコピーする費用がかかる。共有状態を更新して戻すなら、変更した箇所だけを記録すればよい。

booleanを元へ戻すだけでよいのは、入る前の値がfalseだと分かっているからである。一般の配列値を変更するなら、変更前の値を保存して復元する。同じ値を複数回利用し得る制約では、単一のflagより使用回数が必要になる。たとえば残り個数を減らしたなら、復帰時に同じ個数だけ増やす。

取り消すのは分岐に属する状態である。見つけた解の総数や全探索での最良値は、他の枝の結果も集計するため、そのまま残す。

### 何を切り捨ててよいかを、要求から決める

[ABC284 E](/problems/abc284-e/)では、始点からの単純経路の本数と $$10^6$$ の小さい方を求める。経路は終点を選んで止まってよいので、探索木の各状態そのものが一つの数える経路になる。始点だけの経路も含む。

したがって数えた経路が上限に達したら、未探索の枝をすべて打ち切れる。それ以降に経路が増えても、出力が変わらないためである。子から戻った後に上限を確認し、残る隣接候補を試すループも止めよう。その場合も `path` と `used` を元へ戻してから関数を抜ければ、入口・出口の約束を保てる。

別の問題で「長さが指定値に達した経路だけを数える」となれば、答えに加えない途中状態や行き止まりが大量に現れ得る。完成した解の個数だけを上限で止めても、探索量がその個数で抑えられるとは限らない。枝刈りも、現在の部分解をどう延長しても条件を満たせないと示したときに行う。

## 成立条件と計算量

探索中に処理した状態数を $$Q$$、各状態で試す分岐数の上限を $$\Delta$$ とすると、変更と取り消しが定数時間なら探索は $$O(Q(\Delta+1))$$ 時間である。各候補の経路をコピーして保存・出力するなら、経路長の総和も加える。入力のグラフを隣接リストに保存する場合は、前処理と保存に $$O(N+M)$$ を使う。

ABC284 Eでは探索状態と数える経路が一対一なので、上限を $$L$$ とすると $$Q\leq L$$。次数の上限も与えられるため、全体は $$O(N+M+L(\Delta+1))$$ 時間になる。経路と再帰の深さは高々 $$\min(N,L)$$ だが、入力と `used` も含めた全空間は $$O(N+M)$$。深い再帰を使えない環境では、頂点と「次に試す隣接先の位置」をstackに持ち、入る・子へ進む・戻るを同じ順番で行う。

一般のbacktrackingが多項式時間になるわけではない。分岐数と深さから指数的な探索木ができることがある。状態の復元による1回当たりの効率と、探索する状態の総数は分けて評価する。
