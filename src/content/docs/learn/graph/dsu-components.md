# DSUによる連結成分管理・縮約

習得対象の目安: **緑色（800–1199）**。代表と成分サイズを管理し、辺追加による連結性をDSUで処理する。

対象色の読み方は[本書の読み方](/learn/modeling/)を参照してください。

## 概要

### DSUによる連結成分管理・縮約

辺追加や同値関係をDSUで統合し、成分代表と必要な成分metadataを一貫して保つ。

### 習得する技能

- 成分へmetadataまたはmerge履歴を集約し、成分を一頂点に縮約した隣接関係、または併合後の代表情報を構成できる。
- 静的な辺を探索して成分を付けるか、辺追加ごとに成分を併合し、同一成分・サイズを判定できる。

## 考え方

辺を追加した際に二つの成分を代表で併合する。代表は成分の識別子であり、元graphの親ではない。サイズや辺数などを代表に集めれば、連結性と成分の属性を同時に更新できる。


parent[v]=v,size[v]=1で開始する。find(v)は根まで辿り、帰りに親を根へ置き換える。mergeでは二根を探し、違えば小さいsizeの根を大きい根へ付け、sizeと成分属性を加算する。同根なら併合は不要。辺数を持つなら異根の場合はedges_new=edges_a+edges_b+1、同根でもedgesを1増やす。

縮約graphは全元頂点にid[v]=find(v)を付け、元辺の端点をidへ写して作る。自己成分内の辺を省くか保持するか、成分間多重辺を一つへまとめるかは、到達性・費用・個数のどれを保存するかで決める。DSUの親linkは元graphの辺や併合履歴の木として使えない。

## 成立条件と計算量

union by sizeと経路圧縮の併用はQ操作でO((V+Q)α(V))。単純な削除には対応しない。辺を追加して同じ成分だった場合も辺数などは更新する。経路復元には別のgraph情報が必要。

概念上の親: [連結成分を管理し縮約する](/learn/graph/connectivity/)。問題へ進む前に、下記の直接前提のうち未習得の単元を確認する。

直接の前提単元: なし。
