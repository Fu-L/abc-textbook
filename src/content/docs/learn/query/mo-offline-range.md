# Moの順序で区間問い合わせの差分を更新する

このページは **節** です。一つの原子的な技能について、発動条件から正当化・計算量・実装上の境界条件までを再現できる状態を作ります。

読み終えたら、手法名を覚えたかではなく、未知問から発動条件を抽出し、候補を比較し、正当化と計算量を説明できるかで自己評価します。

## 発動条件と見分け方

### Mo's algorithmによるオフライン区間問い合わせ

区間問い合わせを端点の移動量が小さい順に並べ、一要素の追加・削除で答えを更新する。

検索語: Mo's algorithm、Mo法、ムーのアルゴリズム

未知問では、対象・操作・保つべき量・求める量を言葉にし、上の定義をすべて満たすかを確認します。名称の一致だけでは採用しません。

## ガイド例

### 例 1 — 区間問い合わせの順序と追加・削除操作を設計し、端点移動の総量を評価できる

題材: [ABC242 G「Range Pairing Query」](https://atcoder.jp/contests/abc242/tasks/abc242_g)

#### このOutcomeを支える根拠

- 色頻度の pair 総数を O(1) add/remove で維持し、大量 range query を Mo 順で処理できる。

#### 観察

- 区間内で色 c が cnt_c 人なら作れる pair は floor(cnt_c/2) で、答えは色ごとのこの値の和になる。query 間で端点を一つ動かすと変化するのは追加・削除した一色だけである。
- 色を一個追加したとき旧個数が奇数なら pair が1増え、削除時は旧個数が偶数なら1減るため、区間状態を定数時間で更新できる。

#### 候補を比較する

- **採用**: query を Mo's algorithm の順に並べ、現在区間の色頻度と pair 総数を四種類の端点移動で保つ。 — 各 query を独立集計せず、近い区間間で O(1) update を共有でき、Q=10^6にも対応できる。
- **棄却**: 各 query で区間を走査して色頻度を作り直す。 — 長い区間 query が多数あると総走査量が NQ になる。

#### 鍵となる着眼

- 非線形な floor(cnt/2) でも、一個の増減差は cnt の偶奇だけで決まるため Mo の add/remove に必要な十分状態は頻度と総 pair 数だけである。

#### アルゴリズムへ接続する

query を左端 block と右端で Mo 順に sort する。現在 [L,R] を伸縮し、add(x) は count[A_x] が奇数なら ans++、remove(x) は削除前 count[A_x] が偶数なら ans-- として頻度を更新し、元 query index へ ans を保存する。


## 転用するときの確認

- **Mo's algorithm**: 静的配列の多数の offline range query で、要素一個の追加・削除から答えを更新できるとき。 適用: 端点移動総数が小さくなる block 順へ query を並べ替える。
- **頻度関数の差分更新**: 答えが Σg(cnt_c) の形で、cnt を±1した差が簡単なとき。 適用: 対象色の g(new)-g(old) だけを総和へ反映する。
- floor や parity を含む頻度集計では add/remove の差を別々に式で導き、対称だと決めつけない。
- 同じ色の個数を0→1→2→1→0と動かし、pair 数の差と add/remove の判定時点を表にして覚える。
