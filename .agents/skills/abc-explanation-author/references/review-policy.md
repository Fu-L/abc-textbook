# 解説の確認方針

Codexが執筆と品質確認を完結させる。人間・第三者・別エージェントの承認、review mode、work
manifest、review evidence、skill
digestの新規作成を要求しない。確認結果と未解決事項はPR本文または完了報告へ簡潔にまとめる。

1. 公式問題文・個別公式解説とSource Revisionのtask
   identity、fingerprint、claim根拠を照合する。未検証・stale・矛盾したclaimを確定事項として渡さない。
2. 着想から必要な状態・保持する量、初期化・遷移・操作順、答えの取り出し方まで実行できる粒度でつながるかを読む。典型名や計算量の式だけで手順を代用しない。
3. 証明の仮定、対応の双方向性、漏れ・重複、不変条件、終了条件を解法に応じて確認する。空集合、最小入力、同値・重複、到達不能、整数幅など関係する境界を検算する。
4. 前処理・全遷移・データ構造操作・出力を含む全体計算量を評価し、状態数、保持データ、制約と対応させる。掲載した実行可能コードは実行して期待結果を確認する。
5. 学習成果、主配置・関連先、前提、読書順、用語、文章と表示を変更範囲で確認する。

公式根拠間の矛盾では、矛盾箇所と再取得・再確認条件を示して保留する。独自証明では仮定・論証・反例・必要な小例の検算を厚くする。大きな分類変更では変更前後のhome、関連単元、前提、導線を確認する。いずれも別の承認modeへ切り替えない。

旧`reviewMode`や`riskReasons`は過去入力との互換性のために型を検証して読める。旧記録を新規承認として扱わず、確認した事実だけを報告する。
