# Feature Specification: ABC上級問題体系化教科書

**Feature Branch**: `main`

**Created**: 2026-07-12

**Status**: Ready for planning

**Input**: User description: "ABC212以降のE問題以上の全問題から典型を体系化した教科書・問題集と、1人用の簡易な学習管理ツールを作る。"

## Stakeholder Summary

ABC 212以降の上級問題を年代順に並べるだけでなく、必要な典型、考察法、前提知識に沿って横断的に整理した日本語の教科書・問題集を提供する。学習者は分野別の教科書目次、典型タグ、コンテスト表の三方向から問題へ到達し、端末内で解答状況と要復習を管理できる。教材管理者は終了済みの新しいABCを一操作で更新候補にし、追加費用なしの検証とprotected mainへのmergeを経て既存教材へ追加できる。

この仕様で「E問題以上」とは、各ABCの公式問題一覧でD問題より後に並ぶすべての競技問題を指す。現在一般的なE・F・G・Hだけに固定せず、将来Iその他の新しい問題記号が追加された場合も対象に含める。

## Learner and Scope *(mandatory)*

**Target learner**: ABCのA〜D相当を自力で解け、E問題以上へ進むために典型知識と発想法を体系的に学びたい日本語話者。既に上級問題へ挑戦している学習者が、知識の抜けを発見して復習する用途も含む。

**Prerequisites**: 学習開始時点で、いずれか一つの競技プログラミング用言語を使い、次の技能を小規模な問題で説明・実装・確認できることを前提とする。

- 標準入出力、条件分岐、反復、関数を使える。
- 整数、文字列、配列、連想配列、集合を選択し、走査、更新、集計、並べ替えができる。
- 制約から全探索、線形走査、二分探索の計算量を見積もれる。
- 累積和、基本的な貪欲法、一次元の初歩的な動的計画法を説明して実装できる。
- 木、重みなしグラフ、グリッドに対する深さ優先探索と幅優先探索を実装できる。
- 剰余、最大公約数、初歩的な素因数分解を扱い、境界値を含むテストで誤りを切り分けられる。

高度なデータ構造、発展グラフ算法、高度な動的計画法、FFT、発展的組合せ論・数論、問題固有の定理は共通前提に含めない。必要な場合は前提学習単位へのリンクを明示する。分野別の掲載順では前提が後の節・章に現れることを許容し、その位置を読者に知らせる。

**Learning outcomes**:

- 学習者は、対象問題を必要な典型テクニック、考察法、前提知識に結び付けて説明できる。
- 学習者は、依存関係に沿った順で学び、未知の上級問題に対して解法へ至る再現可能な考察手順を組み立てられる。
- 学習者は、階層タグから同じ典型の基本問題、発展問題、複合問題を横断して復習できる。
- 学習者は、コンテスト番号と問題記号から問題、解説、章、タグを逆引きできる。
- 学習者は、問題ごとの解答状況と要復習を記録し、次に取り組む問題を絞り込める。
- 教材管理者は、終了済みの新しいABCを一操作で候補化し、既存の分類・学習順・索引との整合を確認して公開判断できる。

**In scope**:

- ABC 212から各公開版の基準日時点で最新の終了済みABCまでの連続した番号範囲。公式に開催されなかった番号は、別のContestを捏造せず公式欠番証跡で被覆する。
- 各対象ABCで公式問題一覧のDより後に並ぶ、実在するすべての競技問題。
- 公式問題情報と利用可能な公式解説を根拠にした、独自の日本語解説。
- 全対象問題を横断して作る典型タグ、学習成果、前提関係、内部の標準学習順、および分野別の教科書掲載順とUnitの習得対象色。
- 完全解説を基本とし、同じ成果を学ぶ類題・補充問題だけを根拠付きで簡略化する問題集構成。
- コンテスト表、問題一覧、典型タグ、学習単位、検索からの相互参照。
- 解答状況、要復習、各更新日時、絞り込み、バックアップと復元。
- 終了済みABCの差分取得、更新準備、検証、merge、静的デプロイまでの更新体験。
- 既存の個人所有機器と通常の通信環境だけで追加費用なく運用する経路。

**Out of scope**:

- ABC 211以前、ABC以外のコンテスト、A〜D問題の網羅的な解説。
- 開催中コンテストの問題取得、解析、解説公開。
- 公式問題文、公式解説、他者の提出コードの利用条件に反する転載。
- オンラインジャッジ、提出代行、成績順位付け、複数利用者のアカウントや進捗共有。
- 特定言語だけを前提としたリファレンス全集。
- 典型に結び付かない問題固有の発想を、根拠なく独立した必修典型として一般化すること。
- 必須経路での有料API、有料ホスティング、従量課金サービス、継続的な外部参加者調査。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 問題を理解して再現可能な解法を学ぶ (Priority: P1)

学習者は対象問題を選び、着眼点から解法へ進む自然な考察、正当性、計算量、実装上の注意、検証可能な例を順に学ぶ。

**Why this priority**: 分かりやすく再利用可能な解説が教材の中核価値であるため。

**Independent Test**: 任意の対象問題1問について、公式根拠と前提を確認でき、考察から検証までを含む解説を読んだ後に主要な着眼点と解法を説明できれば検証できる。

**Acceptance Scenarios**:

1. **Given** 未学習の対象問題を開いた、**When** 解説を順に読む、**Then** 着眼点、典型、問題固有の要素、解法、正当性、計算量、実装上の注意が説明の飛躍なく示される。
2. **Given** 公式情報と解説候補がある、**When** 公開前に確認する、**Then** 出典、確認日、前提、学習成果、再現可能な例または検証手順を確認できる。
3. **Given** 根拠と解説の主張が食い違う、**When** 公開判定を行う、**Then** 相違が解消されるまで公開されない。

---

### User Story 2 - 典型テクニックを体系的にたどる (Priority: P1)

学習者は全対象問題を横断して整理された典型を、分野ごとに親子Unitがまとまった教科書で学ぶ。掲載順を難易度順や必修の履修順とはせず、各Unitの習得対象色と前提リンクから、今学ぶ節・一旦飛ばす節・先に補う前提を自分で判断する。

**Why this priority**: 問題をコンテスト順に並べるだけでは、元目的である典型の体系化と再利用可能な学びを実現できないため。

**Independent Test**: 複数コンテストにまたがるグラフ、動的計画法、データ構造、数学の問題が共通する典型へ統合され、全Unitが重複なく親子のまとまりで並び、対象色・理由・前提リンクと既存の問題順を確認できる。内部の前提順は別途、前提違反と循環がないことを検証する。

**Acceptance Scenarios**:

1. **Given** 全対象問題の技法と前提の棚卸しがある、**When** 典型体系を作る、**Then** コンテスト番号ではなく学習成果と前提に基づいて問題が統合・分割される。
2. **Given** 複数の学習単位がある、**When** 教科書目次を表示する、**Then** 同じ入力から同じ分野別掲載順が得られ、各親Unitと全子孫が連続し、目次の字下げで階層が分かる。後に掲載された前提には「後の節」または「後の章」を表示する。
3. **Given** 一つの問題に複数の典型がある、**When** 問題またはタグを開く、**Then** 主たる典型、補助的な典型、問題固有の要素が区別される。
4. **Given** 任意のUnitを開いた、**When** 対象色を確認する、**Then** 色名・レーティング帯・選定理由から内容を習得すべき段階を判断でき、全掲載問題を解く難易度とは区別できる。章・構造Unitは導入対象、学習Unitは習得対象として表示する。
5. **Given** Unitの掲載順だけを編集した、**When** 教材を再生成する、**Then** 前提DAG、内部の前提順、各問題の主配置とUnit内の問題順は変わらない。

---

### User Story 3 - 解答状況と要復習を管理する (Priority: P1)

学習者は問題ごとに未着手、挑戦中、修了を記録し、これとは独立して要復習を付け、復習対象を絞り込む。

**Why this priority**: 教科書を継続利用し、学んだ典型を定着させるために最小限必要な管理機能だからである。

**Independent Test**: 一つの問題で解答状況と要復習を別々に変更し、再度開いても値と各更新日時が保持され、要復習一覧へ反映されれば検証できる。

**Acceptance Scenarios**:

1. **Given** 未着手の問題がある、**When** 修了へ変更して要復習を付ける、**Then** 両方の状態と別々の更新日時が保存される。
2. **Given** 要復習の問題が複数ある、**When** 要復習一覧を開いて条件を追加する、**Then** コンテスト、問題記号、典型、章、解答状況で絞り込める。
3. **Given** 教材の分類や章順が変わる、**When** 新版を開く、**Then** 問題IDが同じ既存問題の学習記録は保持される。
4. **Given** 学習記録を別の保存領域へ移したい、**When** バックアップを復元する、**Then** 適用前に差分と競合方針を確認でき、失敗時に一部だけ反映されない。

---

### User Story 4 - 問題やコンテストから逆引きする (Priority: P2)

学習者はコンテスト番号を行、対象問題記号を列とする表、問題名、タグ、章、検索から目的の問題へ移動する。

**Why this priority**: 既知の問題を体系的な教科書へ結び直し、復習時の入口を増やすため。

**Independent Test**: 複数ABCの表を表示し、Dより後のすべての公式問題記号が列として現れ、各収録済みセルから問題、解説、章、タグ、類題へ直接到達できれば検証できる。

**Acceptance Scenarios**:

1. **Given** 対象範囲に複数の問題記号がある、**When** 表を開く、**Then** E〜Hを含むDより後の記号の和集合が公式順の列として表示される。
2. **Given** ある回に列の問題が存在しない、**When** そのセルを見る、**Then** 未収録と混同せず公式問題なしと表示される。
3. **Given** 問題名、タグ名または旧名称、章名、コンテスト番号を入力する、**When** 検索する、**Then** 種別と公開済み参照先を持つ結果だけが表示される。

---

### User Story 5 - 新しいABCを一操作で追加準備する (Priority: P2)

教材管理者は終了済みの未収録ABCを一操作で取り込み候補にし、既存の典型体系、学習順、索引への差分と公開可否を確認する。

**Why this priority**: 対象問題が継続的に増えても網羅性と体系性を保つため。

**Independent Test**: 未収録の終了済みABCを一度の開始操作で処理し、Dより後の全実在問題が重複なく候補化され、問題ごとの草案、要執筆、具体的な保留のいずれかと分類・配置候補が示されれば検証できる。

**Acceptance Scenarios**:

1. **Given** 新しいABCが終了している、**When** 更新を開始する、**Then** Dより後の全問題について出典、解説結果、タグ、前提、章配置、索引候補が一つの更新候補にまとめられる。
2. **Given** 同じ更新を再実行する、**When** 入力に変更がない、**Then** 重複を作らず同じ候補または差分なしを示す。
3. **Given** 根拠不足、未完成解説、循環、壊れた参照がある、**When** 検証する、**Then** 問題ごとの理由を示して公開を保留する。
4. **Given** 適用検査と必要な作成者外レビューが成功した、**When** 管理者がprotected mainへmergeする、**Then** そのGit commitの教科書、問題集、索引、履歴が一つの更新としてデプロイされる。

### Edge Cases

- 公式問題一覧でHがなくGまでしかない回や、将来Iその他の新しい記号が追加された回を扱う。
- 問題が後日取り下げ、改題、訂正された場合に、教材側の作業状態と公式状態を分けて扱う。
- 公式問題は存在するが公式解説が未公開または訂正中の場合、根拠が揃うまで公開を保留する。
- 一問に同等に重要な典型が複数ある場合、主たる典型を無理に一つへ限定しない。
- 類題候補に新しい主成果、前提、主要解法、証明上の着眼点、漸近計算量がある場合は完全解説に戻す。
- 新問題が既存体系に収まらない場合、仮分類を公開体系へ混入させず、全問題を横断した影響を確認してから正式化する。
- 学習状態が未変更なら、現在時刻を補わず更新記録なしと表示する。
- 一部候補だけが失敗した場合、相互参照が不整合になる部分公開を行わない。
- 外部参照が利用不能または取得不可の場合、転載で補わず状態と再確認条件を示す。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教材はABC 212から公開基準日時点で最新の終了済みABCまでを連続した番号範囲として記録し、開催済みContestと公式欠番証跡の和で全番号を被覆したうえで、各開催回の公式問題一覧でDより後に並ぶ実在問題を100%カタログ化しなければならない。
- **FR-002**: 各対象問題枠は公式上の存在・不存在・未確認・取り下げと、教材側の未収録・作成中・公開保留・収録済み・訂正確認中を分けて保持し、空欄のない表示状態を導出しなければならない。
- **FR-003**: 各問題はコンテスト番号、公式問題記号、問題名、公式参照先、制約、難易度の根拠、公開状態、最終確認日を保持しなければならない。
- **FR-004**: 各完全解説は自然な考察手順、典型と問題固有要素の分解、復習時の助言を含まなければならない。
- **FR-005**: 各完全解説は解法の正当性、計算量、制約との整合、実装上の注意、再現可能な例または検証手順を含まなければならない。
- **FR-006**: 外部情報に基づく解説は権威ある出典と確認日を追跡でき、根拠との矛盾が解消されるまで公開できないようにしなければならない。
- **FR-007**: 典型タグと学習単位は全対象問題の技法・前提を横断的に棚卸しした結果から作り、コンテスト番号ごとの一時分類を公開体系の正本にしてはならない。
- **FR-008**: 各正式タグは名称、定義、学習成果、代表問題、親またはルート、教材上の前提タグ、同義語・旧名称に加え、未知問で想起するための対象・発動条件・不変量・目的・除外条件からなるsemantic signatureを持たなければならない。該当する前提ではないTag間関係がある場合は、その型と学習上の理由も保持しなければならない。該当関係がないTagでは空の関係集合を許容し、件数を満たすためだけの関係を作ってはならない。
- **FR-009**: 各問題は一つ以上の典型タグに関連付き、主・補助の典型と問題固有の要素を区別しなければならない。
- **FR-010**: タグの前提関係と学習単位の前提関係を、論理的な最小依存ではなく説明の再利用と自然なprogressionを表す教材上のprecedence constraintとして別々の循環のない関係に保持し、すべての前提が先行する決定的な標準学習順を生成しなければならない。この標準学習順は問題配置・前提検証用の内部順であり、読者向けの教科書掲載順とは区別する。単なる併用、対比、類似、特殊化、拡張、帰着、実装基盤の関係を前提へ押し込んではならない。
- **FR-011**: 各学習単位は共通前提、追加前提または追加前提なし、対象外、必要な概念・アルゴリズムの簡潔な説明、問題一覧を持つ。Tag / Outcomeは分類・前提・関連問題のmetadataとし、各一つのUnitへ直接所属させる。navigation集合は自身と子孫の所属集合の和集合とする。各Problemは一意の`presentationUnitId`を持ち、自然に配置できる場合は葉Unitを選ぶ。`directProblemIds`はそのUnitへの主配置を読む順に並べ、`problemIds`は自身の直接配置と子孫のcoverage、`relatedProblemIds`は範囲外の関連参照とする。教科書掲載順は分野別に定め、親Unitを先頭に全子孫を連続配置する。前提が後に掲載される場合はリンクに「後の節」または「後の章」を付ける。Unit内のProblemは必要Tag / Outcomeの前提、解法の基本性・複合性を優先し、代表順位などと安定IDを最後のtie-breakに使う。掲載順だけの変更で問題配置・Unit内の問題順・内部の前提順を変更してはならない。固定のガイド・転移・評価課題は生成しない。各Problem固有のauthoring unitとfull解説原則を維持する。`contentPhase`で後続の本文執筆へ引き継ぎ、T160までcanonical文書はdraftとする。
- **FR-011a**: 章・構造Unitを含む全UnitにAtCoder Algorithmの色名、対応するレーティング帯、選定理由を表示する。色は上位競技者の観点で、その内容の標準形・適用条件・不変量・計算量を理解し、実装またはライブラリへの帰着を使えるようになるべき対象を編集判断として示す。全掲載問題の完答難度、未知問での発想難度、内部rankや掲載問題の難度集計からは決めない。章・構造Unitは「導入対象の目安」、学習Unitは「習得対象の目安」とし、子孫の最高難度を親に転記しない。公式の色帯と教材独自の習得目安を区別し、必修の履修順や読者の色による閲覧制限には使わない。
- **FR-012**: 各対象問題は完全解説を既定とし、主要な解法・証明・計算量・前提・学習成果が同じと検証できる場合だけ、根拠と差分付きの類題または補充問題にできる。
- **FR-013**: 全対象問題は少なくとも一つの教科書学習単位または典型別問題集から到達可能でなければならず、未分類・参照不能な問題がある版を公開してはならない。
- **FR-014**: コンテスト表は対象範囲で確認されたDより後の問題記号の和集合を公式順の列として生成し、E〜Hに固定せず将来の新しい記号も表示しなければならない。
- **FR-015**: 収録済みの各表セルから問題詳細、解説、対応する学習単位、主・補助タグ、類題へそれぞれ一回の操作で直接移動できなければならない。
- **FR-016**: 公開済みの問題名、タグの正式名・同義語・旧名称、すべての階層の学習単位名、コンテスト番号を検索でき、未公開候補や端末固有状態を検索文書へ混入させてはならない。

### Content Quality Requirements *(mandatory)*

- **CQ-001**: すべての実質的な章、節、解説、例、演習は宣言された学習成果へ追跡できなければならない。

- **CQ-003**: すべての実行可能な例は必要環境、入力、手順、期待結果を明示して公開前に検証し、疑似コードや省略はその種類と範囲を表示しなければならない。
- **CQ-004**: 新しい専門用語は初出で定義し、図、表、色、配置に依存する必須情報には同等のテキスト説明を付けなければならない。

- **CQ-006**: 解説は事実の列挙ではなく、対象学習者が解法へ到達する自然な思考の流れを正確で一貫した日本語で示さなければならない。
- **CQ-007**: 出典の著作権と利用条件を尊重し、必要以上の転載を避け、参照と独自説明によって教材価値を提供しなければならない。

### Key Entities *(include if feature involves data)*

- **Contest**: ABCの回、開催・終了日時、公式参照先、公式問題記号の順序を表す。
- **Advanced Problem Slot**: 公式問題一覧でDより後に並ぶ問題枠。記号、公式順、公式状態、教材状態を持つ。
- **Problem**: 一つの対象問題。コンテスト、問題記号、名称、公式参照、制約、根拠、確認日、公開状態に結び付く。
- **Explanation**: 考察、典型・固有要素、正当性、計算量、例、注意、助言、出典、使用skill版を持つ学習用説明。
- **Technique Tag**: 全対象問題を横断して得た再利用可能な典型または考察法。定義、学習成果、親、教材上の前提、代表問題、同義語、未知問でのrecognitionに使うsemantic signature、前提とは独立した型付きTag間関係を持つ。
- **Learning Unit**: chapter、section、subsectionの教材単位。簡潔な概説、前提、順序付きの主配置問題を持つ。直接所属のTag / Outcomeと子孫を含むnavigation集合、問題の主配置とcoverage・関連参照を区別する。
- **Problem Placement**: 問題と主・補助Tag/Outcomeを結び、各Outcomeを直接所有するUnitだけを配置先とし、主Outcome所有者から一意な表示Unitを選ぶ。完全解説、類題、補充問題の別と判定根拠も表す。
- **Source Revision**: 公式情報の確認版、確認日時、指紋、訂正系列、利用条件を表す。
- **Correction Impact**: 出典や分類の変更がProblem本文・例・演習・解答・配置、LearningUnit本文・例・演習・解答・学習順、および派生索引へ与える影響を、所有者・具体的locator・全Source Revision・検証状態とともに表す。
- **Learning Record**: 一人の学習者について、問題ID、解答状況、要復習、各更新日時を表す。
- **Learning Record Backup**: 学習記録、形式版、作成日時、対象教材版を持つ可搬ファイル。
- **Publication Update**: 一回の追加・訂正・再編の候補と検証結果をまとめる単位。
- **Release Metadata**: version、cutoff、full Git commit hash、更新概要、検証結果URLだけを持つdeployment入力。snapshot自体はGit commitが所有する。
- **Release**: Git commitで識別され、取り込んだ更新、変更履歴、検証要約をCatalogから追跡できる不変の公開版。
- **Authoring Skill**: 解説候補を一貫して作る版付きの執筆指示。
- **Review Evidence**: 対象、学習成果、固定したreview risk policy、自動検査、自己reviewまたは第三者reviewの判定、指摘と解消結果を結び付ける記録。通常更新の証跡は外部person IDを要求せず、高リスク更新は原則として第三者reviewを使う。solo maintainerの例外ではrisk reasonと`solo_maintainer`理由を保持した`self` modeを明示する。

## Assumptions

- 教材の主言語は日本語とする。
- ABC 212〜466は2026-07-12時点の初期制作シードであり、公開上限ではない。初版直前に終了済みの最新ABCまで追随する。
- 問題記号は文字列として保持し、対象判定は固定列挙ではなく公式問題一覧でDより後に現れる順序による。
- 問題の難易度は単一値で断定せず、公式情報、必要前提、対象学習者にとっての段階を根拠として扱う。
- 公式問題情報と利用可能な公式解説を第一の根拠とし、補助資料を使う場合も出典と確認日を残す。
- 解説生成が利用できない場合も、更新は必要入力と手動テンプレートを作って要執筆として保留できる。これを完成草案には数えない。
- 運用者、教材管理者、継続利用する学習者は同じ一人である。SC-009とSC-010の自己評価もこの運用者が事前固定した対象と採点基準で行う。
- 通常更新の完全自動判定できない新規・変更された主張や例はmanifest ownerの`self` reviewで確認する。FR-026に列挙した固定高リスク条件では原則として`third_party` reviewを行うが、maintainerが一人だけの場合は明示的な`solo_maintainer` high-risk self-reviewを利用できる。この限定的なレビュー役は製品利用者や継続運用者ではなく、複数利用者機能を意味しない。
- 公開前の品質判定に有料サービスや特定のLLM利用を必須にしない。任意の補助判定を利用しても、必須の自動検査と人間レビューを代替しない。
- 学習記録は問題IDへ結び付け、完全な変更履歴ではなく解答状況と要復習それぞれの最新変更日時を保持する。
- 無料とは、既に所有する機器、電気料金、通常のインターネット接続料金を除く追加の必須支出が0円であることを指す。
- AtCoderおよび参照資料の利用条件に従い、問題文や公式解説は必要最小限の引用と参照を基本とする。
