# Feature Specification: ABC上級問題体系化教科書

**Feature Branch**: `N/A (specification only)`

**Created**: 2026-07-12

**Status**: Draft

**Input**: User description: "AtCoder Beginner Contestの#212以降のすべてのE, F, G, H問題を、専用の解説生成skillを用いて分かりやすく解説し、典型テクニックの階層タグと学習上の依存関係による順序で整理する。コンテスト番号×問題スロットの表から逆引きでき、問題別の学習状態を管理でき、毎週のコンテスト後に一操作かつ追加費用なしで更新できる1人用の教科書・問題集を作る。"

## Learner and Scope *(mandatory)*

**Target learner**: ABCのA〜D相当を自力で解け、E以降へ進むために典型知識と発想法を体系的に学びたい日本語話者。既に上級問題へ挑戦している学習者が、知識の抜けを発見して復習する用途も含む。

**Prerequisites**: いずれか一つの競技プログラミング用言語で基本的な実装ができること、計算量の初歩、配列・集合・再帰・基本的なグラフ探索、ABC D相当までの標準的内容を理解していること。各章は、これを超える前提知識を章冒頭で明示する。

**Learning outcomes**:

- 学習者は、ABC 212以降の対象問題を、必要な典型テクニックと前提知識に結び付けて説明できる。
- 学習者は、依存関係に沿った章順で学び、未知の対象問題に対して解法へ至る再現可能な考察手順を組み立てられる。
- 学習者は、階層タグから関連問題を選び、同じ典型の基本問題、発展問題、類題を横断して復習できる。
- 学習者は、コンテスト番号を行、問題スロットを列とする表から対象問題・解説・章・タグを逆引きできる。
- 学習者は、問題ごとの解答状況と「要復習」タグを記録し、要復習問題だけを取り出して次に取り組む問題を絞り込める。
- 教材管理者は、終了済みの新しいABCを一操作で取り込み候補に加え、既存教材との整合性を検証して公開判断できる。

**In scope**:

- ABC 212から教材の公開基準日時点で公式に公開済みの各ABCについて、E・F・G・Hという問題記号のうち実在する全問題を収録対象として管理する。
- 各対象問題の問題情報、公式問題文への参照、公式解説等の根拠、構造化された日本語解説、典型・アドホック要素、演習上の位置付けを扱う。
- 典型テクニックを、ジャンルごとに必要な深さを持つ階層タグとして整理し、タグ間の前提関係を循環のない学習依存関係として定義する。
- 学習依存関係、難易度、基礎から発展への自然さを反映した章・節・問題の学習順を提供する。
- chapter、section、subsectionを統一された学習単位として依存関係に基づき整列し、先頭から順に読める一本道の標準学習経路を提供する。同じ分野が異なる習熟段階で非連続に再登場する構成を許容する。
- ほぼ同一の問題は類題・補充問題として簡略化できるが、対象問題としての収録記録、相違点、参照先、対応タグは残す。
- AtCoder Problems型の、コンテスト番号を行、E・F・G・Hの問題スロットを列とする表形式索引、および問題名、階層タグ、章からの索引と相互参照を提供する。
- 問題ごとの解答状況と「要復習」タグを管理し、表形式索引と問題一覧にバッジとして反映し、タグ付き問題だけの一覧を提供する。
- 現在ルート直下の `prompt.md` に置かれている解説方針を、再利用可能で版管理された専用skillとして整備し、教材生成がルート直下の一時ファイルに依存しない状態にする。
- 毎週のコンテスト終了後に行う差分取得、解説候補生成、分類候補作成、検証、承認、公開までの更新体験を扱う。
- 既存の個人所有機器と通常の通信環境を除き、必須機能を継続費用0円で1人が運用できるようにする。

**Out of scope**:

- ABC 211以前、ABC以外のコンテスト、および原則としてA〜D問題の網羅的な解説。
- 開催中のコンテストからの取得または解説公開。
- AtCoderの問題文・解説・提出コードを、利用条件に反して転載すること。
- 特定のプログラミング言語だけを前提にしたリファレンス全集、オンラインジャッジ機能、提出代行、成績順位付け。
- 複数利用者のアカウント、権限、進捗共有、ランキング、共同学習機能。
- 必須機能の利用に有料契約、従量課金サービス、常時稼働する有料ホスティングを要求すること。
- 典型テクニックと結び付かないアドホックな発想だけを、独立した必修章として過度に一般化すること。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 問題を理解して再現可能な解法を学ぶ (Priority: P1)

学習者は対象問題を選び、単なる解答の要約ではなく、初見時にどこへ注目し、なぜその解法へ進むのかを段階的に学ぶ。解説から典型知識、問題固有の発想、復習時の要点、検証可能な例へ移動できる。

**Why this priority**: 分かりやすく再利用可能な解説が教材の中核価値であり、分類や更新機能だけでは学習成果を生まないため。

**Independent Test**: 任意の対象問題1問について、問題情報と根拠を入力し、専用の解説生成skillが要求する「自然な考察手順」「学ぶべきパーツの分解」「ワンポイントアドバイス」を備え、前提・例・検証方法まで含む解説を学習者が閲覧できれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 未学習の対象問題を開いた学習者がいる、**When** 解説を順に読む、**Then** 問題の着眼点から解法、正当性、計算量、実装上の注意へ至る論理が、未定義の専門語や説明の飛躍なしに示される。
2. **Given** 解説生成に必要な公式問題情報と公式解説が参照可能である、**When** 専用の解説生成skillで解説候補が作られる、**Then** skillの全必須区分を満たし、出典、確認日、前提知識、学習成果、検証可能な例または検証手順が付く。
3. **Given** 公式解説と生成された説明の主張が食い違う、**When** 公開前検証を行う、**Then** 相違が解消または明示されるまでその解説は公開可能状態にならない。

### User Story 2 - 典型テクニックを学習順にたどる (Priority: P1)

学習者は「データ構造」「数学」「グラフ」などの大分類から、個別のデータ構造やアルゴリズム、さらに「転倒数の計算」「セグメント木上の二分探索」のような応用へ降り、前提を満たす順序でchapter、section、subsectionを先頭から学ぶ。DPの基礎を学んだ後、別の高度なデータ構造を挟み、その組合せとしてDPが再登場するような段階的構成も自然な学習経路として扱う。

**Why this priority**: 問題を年代順に並べるだけでは知識の依存関係が隠れ、最強の教科書としての体系性と段階的学習を実現できないため。

**Independent Test**: 代表的な複数ジャンルのタグ、学習単位、前提関係、対象問題を登録し、chapter・section・subsectionを横断して循環のない全体順序と、各単位の前提・学習成果・基本問題・発展問題が表示されることで検証できる。

**Acceptance Scenarios**:

1. **Given** 階層タグ、学習単位、両者の前提関係が定義されている、**When** 学習順を表示する、**Then** chapter・section・subsectionのすべてで、前提となる学習単位が依存先より前に現れ、先頭から順に読める一貫した順序になる。
2. **Given** ある問題が複数の典型を組み合わせる、**When** 問題詳細を見る、**Then** 主たる典型、補助的な典型、各タグの階層位置、推奨前提章が区別して示される。
3. **Given** タグの深さがジャンルごとに異なる、**When** 教科書目次を見る、**Then** 不要な空階層を作らず、各末端タグが学習上意味のある技能または問題群を表す。
4. **Given** 前提関係に循環が持ち込まれた、**When** 公開前検証を行う、**Then** 循環を構成するタグが示され、解消するまで章順は公開更新されない。
5. **Given** 同じ分野の基礎編と複合・発展編がある、**When** 全体の学習順を作る、**Then** それぞれを必要な前提の直後に別の学習単位として配置でき、同一分野を一箇所にまとめるために前提順を崩さない。

### User Story 3 - 解答状況と要復習タグを管理する (Priority: P1)

1人の学習者は、各問題について「未着手」「挑戦中」「修了」という解答状況を記録し、それとは独立して「要復習」タグを付け外しできる。それぞれを最後に変更した日時を確認し、「要復習」タグ付きの問題だけを取り出して復習できる。

**Why this priority**: 大量の対象問題を継続学習するには、教材を読む機能だけでなく、自分がどこまで進み、何を復習すべきかを失わないことが不可欠なため。

**Independent Test**: 任意の問題を「修了」にして「要復習」タグを付け、表形式索引を離れて再度開いた後も両方の状態と個別の最終更新日時が保持され、要復習問題だけの一覧から同じ問題へ戻れれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 未着手の問題がある、**When** 学習者が学習を始めてから必要な学習を終える、**Then** 解答状況を「未着手」から「挑戦中」、「修了」へ変更でき、解答状況の最終更新日時が変更ごとに記録される。
2. **Given** 修了したが定着していない問題がある、**When** 学習者が「要復習」タグを付ける、**Then** 解答状況は「修了」のまま保持され、問題には視認可能な「要復習」バッジが現れ、タグの最終更新日時だけが更新される。
3. **Given** 「要復習」タグ付きの問題が複数ある、**When** 学習者が要復習問題の抽出を選ぶ、**Then** タグ付き問題だけの一覧が表示され、コンテスト、問題スロット、タグ、章でさらに絞り込める。
4. **Given** 複数の学習状態を持つ問題がある、**When** 表形式索引または問題一覧を見る、**Then** 各問題の解答状況と「要復習」バッジを区別でき、状態で絞り込める。
5. **Given** 新しいコンテストを教材へ追加する、**When** 既存問題と索引が更新される、**Then** 既存問題の学習状態は失われず、新規問題は「未着手」、要復習タグなし、かつ両方とも「更新記録なし」として扱われる。
6. **Given** 学習状態が一度以上変更された問題がある、**When** 問題の学習記録を確認する、**Then** 解答状況と要復習タグについて、現在値とそれぞれの最終更新日時を日付・時刻・タイムゾーンが判別できる形式で確認できる。

### User Story 4 - 問題やコンテストから表で逆引きする (Priority: P2)

学習者は、AtCoder ProblemsのようにABC番号を行、E・F・G・Hの問題スロットを列にした表から目的の問題を見つける。また、問題名、タグ、章のいずれかからも解説と関連問題へ移動する。

**Why this priority**: コンテスト後の復習や既知問題の再訪では、学習順だけでなく出典側から素早く探せることが重要なため。

**Independent Test**: 複数のABCを行、E・F・G・Hを列とする表を表示し、交点のセルから正しい問題詳細へ到達して、そこから章とタグへ往復できれば検証できる。

**Acceptance Scenarios**:

1. **Given** ABC 212以降の収録済みコンテストがある、**When** 表形式索引を開く、**Then** 各行が一つのABC番号、各列がE・F・G・Hスロットを表し、実在する問題のセルから対象問題の解説へ直接移動できる。
2. **Given** 問題が完全解説ではなく類題・補充問題として扱われる、**When** 逆引きする、**Then** 問題が欠落せず、簡略化理由、元となる主要解説、差分として学ぶ点が示される。
3. **Given** ある回にE〜Hの一部の問題記号が公式に存在しない、**When** その回を表示する、**Then** 対応セルは実在しない枠を未収録と誤認させず「公式問題なし」と区別する。
4. **Given** 各問題に学習状態が記録されている、**When** 表形式索引を見る、**Then** 問題セル内または同じセルに結び付く表示から解答状況と「要復習」バッジを判別でき、必要に応じてそれぞれの最終更新日時を確認できる。

---

### User Story 5 - 新しいABCを一操作で追加準備する (Priority: P2)

教材管理者は毎週のABC終了後、単一の開始操作で新規問題の取得から解説・タグ・掲載位置の候補作成と検証を開始し、結果を確認して公開を承認できる。

**Why this priority**: 対象問題は継続的に増えるため、更新負担を抑えなければ網羅性と品質を長期維持できないため。

**Independent Test**: 未収録の終了済みABCを用意し、一度の開始操作によって実在するE〜Hだけが重複なく候補化され、公開可否と要修正事項がまとめて提示されることで検証できる。

**Acceptance Scenarios**:

1. **Given** 新しいABCが終了し必要な公式情報が公開されている、**When** 管理者が更新開始を1回操作する、**Then** 実在する対象問題、解説候補、タグ候補、依存関係候補、章内位置、索引更新候補が一つの更新単位として準備される。
2. **Given** 同じ更新を再度開始する、**When** 既に候補または公開済みの問題が見つかる、**Then** 重複項目は作られず、変更がある項目だけが差分として示される。
3. **Given** 出典不足、解説区分不足、再現不能な例、分類の循環、壊れた参照のいずれかがある、**When** 更新結果を確認する、**Then** 問題ごとの失敗理由が示され、品質条件を満たさない項目は公開されない。
4. **Given** 全検証を通過した候補がある、**When** 管理者が内容を承認する、**Then** 教科書、タグ別問題集、コンテスト逆引き、関連問題の参照が同じ更新として矛盾なく公開される。
5. **Given** 既存の個人所有機器と通常の通信環境がある、**When** 管理者が週次更新を実行する、**Then** 有料契約または従量課金サービスへの登録を要求されず、追加請求なしで完了できる。

### Edge Cases

- 公式にはE〜Hの一部が存在しない回、問題記号体系が変更された回、問題が後日取り下げまたは訂正された回を、欠落や取得失敗と区別する。
- 公式問題情報は存在するが公式解説の公開が遅い、複数形式に分かれる、または後日訂正される場合、根拠が揃うまで公開を保留し、公開後も影響する説明を再検証する。
- 1問に複数の同等に重要な典型がある場合、主タグを無理に一つへ限定せず、章の重複掲載を避けつつ複数の学習経路を示す。
- ほぼ同一と判定した問題にも重要な制約差・解法差がある場合、完全省略せず差分解説を要求する。
- タグの統合・名称変更・親変更が発生しても、既存問題・章・索引の参照を失わず、旧名称からも追跡できるようにする。
- 学習順を変更または学習単位を分割しても、問題の学習状態を問題そのものに結び付けたまま保持し、旧章位置に閉じ込めない。
- 「修了」の問題に「要復習」タグが付いている場合、矛盾として上書きせず、解答状況とタグをそれぞれ表示する。
- 学習状態がまだ一度も明示的に変更されていない場合、最終更新日時を現在時刻で補わず「更新記録なし」と区別する。
- 新規問題が既存の分類に収まらない場合、仮タグとして明示し、学習成果と前提関係のレビューなしに正式分類へ加えない。
- 一部の更新候補だけが検証に失敗した場合、成功分と失敗分を明示し、教科書全体の相互参照が不整合になる部分公開は行わない。
- 外部参照先が利用不能、アクセス制限、または利用条件上取得不可の場合、無断転載で補わず、状態と再試行・手動確認の必要性を示す。
- 無料で利用できていた外部依存先が有料化または終了した場合、必須機能を課金へ自動移行せず、無料の代替経路または手動手順を示す。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教材は、ABC 212から公開基準日時点の最新の終了済みABCまでを連続した対象範囲として記録し、各回に公式に存在するE・F・G・H問題を100%カタログ化しなければならない。
- **FR-002**: 各コンテスト回について、対象問題記号が「収録済み」「作成中」「公開保留」「公式問題なし」のいずれであるかを区別できなければならない。
- **FR-003**: 各問題記録は、コンテスト番号、問題記号、問題名、公式参照先、制約、難易度の根拠、公開・更新状態、最終確認日を保持しなければならない。
- **FR-004**: 各完全解説は専用の解説生成skillの必須構成に従い、「自然な考察手順」「典型とアドホックに分けた学ぶべきパーツ」「コーチからのワンポイントアドバイス」を含まなければならない。
- **FR-005**: 各完全解説は、解法の正当性、計算量、制約との整合、実装上の注意、再現可能な例または検証手順を含まなければならない。
- **FR-006**: 解説候補は、公式問題情報および利用可能な公式解説を根拠とし、出典と確認日を追跡でき、根拠と矛盾する内容を解消するまで公開できないようにしなければならない。
- **FR-007**: 教材は、典型テクニックと典型的な考察法を、ジャンルごとに必要な深さを選べる親子関係付きタグとして表現しなければならない。
- **FR-008**: 各正式タグは、名称、短い定義、学習成果、前提タグ、親タグ、代表問題を持ち、同義語または旧名称から追跡できなければならない。
- **FR-009**: 各問題は、一つ以上の典型タグに関連付け、主たる典型と補助的な典型を区別し、問題固有のアドホック要素は典型タグと混同せず記録しなければならない。
- **FR-010**: タグとchapter・section・subsectionからなる学習単位の前提関係は循環を許さず、すべての前提学習単位が依存先より前に現れる全体学習順を生成できなければならない。
- **FR-011**: 前提関係だけでは順序が一意に定まらない場合、教材は難易度、基礎から応用への自然さ、代表性に基づく一貫した順序を示し、その順序の理由を読者が確認できるようにしなければならない。

- **FR-034**: 学習者は問題ごとに、現在の解答状況とその最終更新日時、「要復習」タグの有無とその最終更新日時を確認でき、日時表示から日付、時刻、タイムゾーンを一意に判別できなければならない。
- **FR-035**: 解答状況の変更は解答状況の最終更新日時だけを、「要復習」タグの付け外しはタグの最終更新日時だけを更新し、変更していない側の日時を上書きしてはならない。
- **FR-036**: 学習者は一つの操作で「要復習」タグ付き問題だけの一覧を表示でき、その一覧をコンテスト、問題スロット、典型タグ、章、解答状況で追加絞り込みできなければならない。

### Content Quality Requirements *(mandatory)*

- **CQ-001**: すべての実質的な章・節・解説・演習は、宣言された学習成果のいずれかに対応し、その対応を追跡可能にしなければならない。
- **CQ-002**: 外部情報または時点に依存する主張は、権威ある出典、対象となる版またはコンテスト、確認日を明記しなければならない。
- **CQ-003**: すべての実行可能な例は、必要環境、入力、手順、期待される観察可能な結果を明示し、公開前に記載手順で検証しなければならない。
- **CQ-004**: 新しい専門用語は初出時に定義し、図・表・色・配置に依存する必須情報には、公開形式が対応する範囲で同等のテキスト説明を付けなければならない。
- **CQ-005**: 演習は学習成果に対応し、最終答案だけでなく、考え方または検証方法を含む解答資料を持たなければならない。
- **CQ-006**: 解説は専用の解説生成skillのコーチング方針に従い、事実の列挙ではなく解法を自然に導く思考過程を、正確な専門用語と読みやすい日本語で示さなければならない。
- **CQ-007**: 出典の著作権および利用条件を尊重し、必要以上の転載を避け、参照と独自の説明によって教材価値を提供しなければならない。

### Key Entities *(include if feature involves data)*

- **Contest（コンテスト）**: ABCの回を表す。番号、開催・終了時点、公式参照先、対象記号の存在状態、取り込み状態を持つ。
- **Problem（問題）**: 一つの対象問題を表す。コンテスト、問題記号、名称、公式参照先、制約、根拠、確認日、掲載形態、公開状態に結び付く。
- **Explanation（解説）**: 問題の学習用説明。考察手順、典型・アドホック要素、正当性、計算量、例、注意点、助言、根拠、レビュー状態を持つ。
- **Technique Tag（典型タグ）**: 再利用可能な知識または考察法。定義、学習成果、親子関係、同義語、代表問題を持つ。階層の深さは固定しない。
- **Prerequisite Relation（前提関係）**: あるタグを学ぶ前に必要な別タグを表す。学習順を制約し、循環してはならない。
- **Learning Unit（学習単位）**: chapter、section、subsectionのいずれかとして配置される教材単位。階層上の親、前提単位、成果、説明、例、問題群、到達確認、全体学習順を持つ。同じ分野に複数の学習単位が存在できる。
- **Problem Placement（問題配置）**: 問題と章・タグを結ぶ位置付け。主・補助タグ、完全解説・類題・補充問題の別、難易度、主要解説との差分を表す。
- **Source Record（出典記録）**: 技術的主張の根拠となる公式情報、対象版またはコンテスト、確認日、訂正履歴を表す。
- **Publication Update（公開更新）**: 一回の週次追加または修正の単位。対象問題、候補差分、検証結果、レビュー、承認、公開版をまとめる。
- **Index Entry（索引項目）**: コンテスト、問題、タグ、章から相互参照するための項目。参照先と表示状態を持つ。
- **Authoring Skill（解説生成skill）**: 解説候補を一貫して作るための再利用可能な執筆指示。版、目的、入力、必須出力、行動規則、品質確認方法を持つ。
- **Learning Record（学習記録）**: 1人の学習者と問題を結ぶ個人記録。「未着手」「挑戦中」「修了」の解答状況、「要復習」タグの有無、それぞれの最終更新日時を持ち、教材構成が変わっても問題に追随する。

## Assumptions

- 教材の主言語は、現行の `prompt.md` と利用者要件に合わせて日本語とする。
- 「ABC 212以降」はABC 212を含み、初版では公開基準日時点まで、以後は終了した新規ABCを継続追加する意味とする。
- 「E, F, G, H問題」は、各回にその問題記号が公式に存在する場合だけを対象とし、存在しない記号を欠落扱いにはしない。
- 初版の基礎前提としてABC D相当までを要求できるが、E〜Hの各章で追加の前提を明示し、必要に応じて短い補助教材へ誘導する。
- 問題の難易度は単一の数値だけで断定せず、公式情報、解法に必要な前提、対象学習者にとっての段階を根拠として扱う。
- 公式問題情報と公式解説が正確性確認の第一の根拠であり、補助資料を使う場合も出典と確認日を残す。
- コンテスト終了直後に公式解説などの必要情報が揃わない場合、一操作の更新は保留理由までを生成し、根拠が揃う前の自動公開はしない。
- 最終公開には教材管理者の承認が必要であり、自動生成は公開候補の作成と検証を支援する位置付けとする。
- AtCoderおよび参照資料の利用条件に従い、問題文や公式解説は必要最小限の引用と参照を基本とする。
- 現行の `prompt.md` は初期内容の移行元に限り、移行後はルート直下から除去または案内だけを残し、専用の解説生成skillを唯一の正本とする。
- 学習状態は、解答状況を「未着手」「挑戦中」「修了」の排他的な1値、復習の必要性を独立した「要復習」タグの有無として扱う。これにより「修了しているが要復習」を表現する。
- 解答状況と「要復習」タグの更新日時は別々に管理し、利用者のタイムゾーンを伴う日時として表示する。完全な変更履歴ではなく、それぞれの最新変更日時だけを初期範囲とする。
- 運用者、教材管理者、学習者は同一の1人であり、複数端末間の自動同期や他者との進捗共有は初期範囲に含めない。
- 1人用という製品範囲はconstitutionが要求する第三者の内容レビューを免除しない。レビュー担当者は本教材の利用者アカウントを持つ必要はなく、確認記録だけを取り込めればよい。
- 「無料」は、既に所有する機器、電気料金、通常のインターネット接続料金を除く追加の必須支出が0円であることを指す。任意の有料サービスは必須経路に含めない。
- 本機能は専用の解説生成skill、無料で参照可能な公式コンテスト情報、公式解説へアクセスできることに依存する。
