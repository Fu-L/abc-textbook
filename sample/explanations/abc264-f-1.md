# ABC264 F - Monochromatic Path 解説

AtCoder Beginner Contest 264 · F問題 · 500点

この問題は、**行・列の反転を XOR で表現し、経路を1マスずつ伸ばしながら DP する問題**です。

特に重要なのは、次の2つの着眼点です。

- 右または下にしか進めないため、移動するたびに「新しい行」か「新しい列」が1つ登場する。
- 隣接する2マスの色を等しくする条件から、新しく登場した行・列を反転するかどうかが一意に決まる。

これにより、すべての行・列の反転方法を探索する必要がなくなり、**\(O(HW)\) 時間の DP** で解けます。

## 1\. 問題の整理

\(H\times W\) の白黒グリッドがあり、各マスの初期色は \(A_{i,j}\in\{0,1\}\) です。

行 \(i\) を反転すると \(R_i\) 円、列 \(j\) を反転すると \(C_j\) 円かかります。

反転操作を適切に行い、左上 \((1,1)\) から右下 \((H,W)\) まで、**右・下への移動だけで、同じ色のマスのみを通る経路**を作るための最小費用を求めます。

制約は \(H,W\le 2000\) です。citeturn258722search0

## 2\. 解法に至る考察

### 2.1. 反転操作を XOR で表す

同じ行や列を2回反転すると元に戻るため、各行・列について、反転するかしないかだけを決めれば十分です。

行 \(i\) を反転するかどうかを \(x_i\)、列 \(j\) を反転するかどうかを \(y_j\) とします。

それぞれ \(0\) が反転しない、\(1\) が反転することを表します。

すると、操作後のマス \((i,j)\) の色は

\[
B_{i,j}=A_{i,j}\oplus x_i\oplus y_j
\]

です。

費用は

\[
\sum_{i=1}^{H}R_ix_i+\sum_{j=1}^{W}C_jy_j
\]

となります。

素朴には \(H+W\) 個のビットをすべて決めるため \(2^{H+W}\) 通りあります。しかし、本当にこれらを独立に決める必要があるでしょうか。

### 2.2. 経路上の隣接マスに注目する

色がすべて同じ経路であるためには、**経路上で連続する2マスの色が常に等しい**ことが必要十分です。

例えば、現在 \((i,j)\) にいて、右の \((i,j+1)\) に進む場合を考えます。

操作後の色が等しい条件は、

\[
A_{i,j}\oplus x_i\oplus y_j
=
A_{i,j+1}\oplus x_i\oplus y_{j+1}
\]

です。

両辺に共通する \(x_i\) は打ち消されるので、

\[
\boxed{
y_{j+1}=y_j\oplus A_{i,j}\oplus A_{i,j+1}
}
\]

が得られます。

これは重要な式です。

**現在の列の反転状態 \(y_j\) がわかれば、次の列の反転状態 \(y_{j+1}\) は自動的に決まります。**

同様に、下へ進む場合は

\[
\boxed{
x_{i+1}=x_i\oplus A_{i,j}\oplus A_{i+1,j}
}
\]

です。

したがって、現在の行と列の反転状態さえ把握していれば、次のマスを同じ色にするために必要な操作がわかります。

### 2.3. 小さい具体例で考える

入力例1のグリッドを使います。

初期グリッド

0が白、1が黒。行の反転費用は (4, 3, 5)、列の反転費用は (2, 6, 7, 4)。

左上から下に進んで \((2,1)\) に移動することを考えます。

まず、\(x_1=y_1=0\) として開始すれば、\((1,1)\) の色は \(0\) です。

\((2,1)\) の初期色は \(1\) なので、何もしないと異なる色になります。

ここで先ほどの式を使うと、

\[
x_2=x_1\oplus A_{1,1}\oplus A_{2,1}
=0\oplus0\oplus1=1
\]

です。

つまり、2行目を反転する必要があり、費用は \(R_2=3\) 円です。

続いて \((2,1)\) から右へ \((2,2)\) に進むと、

\[
y_2=y_1\oplus A_{2,1}\oplus A_{2,2}
=0\oplus1\oplus0=1
\]

です。

今度は2列目を反転するため、追加で \(C_2=6\) 円かかります。

以降の経路も同様に追えます。

| 移動先 | 新たに決まる反転 | 追加費用 |
|--------|--------|--------|
| \((2,1)\) | \(x_2=1\) | 3 |
| \((2,2)\) | \(y_2=1\) | 6 |
| \((2,3)\) | \(y_3=0\) | 0 |
| \((2,4)\) | \(y_4=0\) | 0 |
| \((3,4)\) | \(x_3=0\) | 0 |

結果として、反転するのは2行目と2列目だけで、費用は \(3+6=9\) 円です。

反転後のグリッドと選んだ経路

緑色のマスが選んだ経路。初期色が異なっていた場所でも、必要な行・列の反転を行うことで、すべて白の経路を作れています。

ここまでの議論から、特定の経路と最初の行・列の反転状態を決めれば、その経路を単色にする操作が一意に決まることがわかります。

### 2.4. なぜ DP が成立するのか

ここで、経路が右または下にしか進めないという条件が効いてきます。

例えば、\((i,j)\) から右へ進むとき、列 \(j+1\) は経路上で初めて訪れる列です。

その列の反転状態を決めても、既に訪れたマスの色は変わりません。また、今後その列に沿って下へ移動することがあっても、反転状態はそのまま使えます。

下へ進む場合も同様です。

つまり、経路を伸ばすたびに、新しく登場した行・列についてのみ反転の費用を払えばよく、過去に決めた反転状態を変更する必要がありません。

そして、次の反転状態を決めるために必要な過去の情報は、現在の \(x_i,y_j\) の2ビットだけです。

これが DP の状態を小さくできる理由です。

## 3\. DP の設計

### 3.1. 状態

次のように定義します。

\[
\boxed{\mathrm{dp}[i][j][x][y]}
\]

これは、マス \((i,j)\) まで単色の経路を作って到達し、現在の行 \(i\) の反転状態が \(x\)、列 \(j\) の反転状態が \(y\) であるときの最小費用です。

各マスについて反転状態は \(2\times2=4\) 通りしかありません。

### 3.2. 初期化

最初のマス \((1,1)\) では、1行目と1列目を反転するかどうかを自由に決めます。

\[
\mathrm{dp}[1][1][x][y]=xR_1+yC_1
\]

これを \(x,y\in\{0,1\}\) の4通りについて行います。

重要なのは、**経路を白にするか黒にするかを固定する必要がない**ことです。

隣接するマス同士の色が等しいという条件だけを維持すれば、経路全体の色は自然に統一されます。

### 3.3. 右への遷移

\((i,j)\) から \((i,j+1)\) に進む場合、行の反転状態 \(x\) は変わりません。

新しい列の反転状態は、

\[
y'=y\oplus A_{i,j}\oplus A_{i,j+1}
\]

と決まります。

新しい列を反転するなら費用 \(C_{j+1}\) を払うため、

\[
\begin{aligned}
&\mathrm{dp}[i][j+1][x][y']\\
&\quad\gets\min\left(
\mathrm{dp}[i][j+1][x][y'],
\mathrm{dp}[i][j][x][y]+y'C_{j+1}
\right)
\end{aligned}
\]

と更新します。

### 3.4. 下への遷移

\((i,j)\) から \((i+1,j)\) に進む場合は対称的です。

新しい行の反転状態は、

\[
x'=x\oplus A_{i,j}\oplus A_{i+1,j}
\]

なので、

\[
\begin{aligned}
&\mathrm{dp}[i+1][j][x'][y]\\
&\quad\gets\min\left(
\mathrm{dp}[i+1][j][x'][y],
\mathrm{dp}[i][j][x][y]+x'R_{i+1}
\right)
\end{aligned}
\]

と更新します。

### 3.5. 答え

右下まで到達した状態の最小値が答えです。

\[
\boxed{
\min_{x,y\in\{0,1\}}
\mathrm{dp}[H][W][x][y]
}
\]

マスの走査順序は上から下、各行について左から右で問題ありません。どの遷移も右か下にしか進まないためです。

## 4\. C++23 実装

```cpp

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int H, W;
    cin >> H >> W;

    vector<ll> R(H), C(W);
    for (auto& x : R) cin >> x;
    for (auto& x : C) cin >> x;

    vector<string> A(H);
    for (auto& s : A) cin >> s;

    constexpr ll INF = (1LL << 60);
    using State = array<array<ll, 2>, 2>;

    vector dp(H, vector<State>(W));
    for (auto& row : dp) {
        for (auto& state : row) {
            for (auto& a : state) a.fill(INF);
        }
    }

    // dp[i][j][x][y]:
    // 現在の行・列の反転状態が x, y のときの最小費用

    for (int x = 0; x < 2; ++x) {
        for (int y = 0; y < 2; ++y) {
            dp[0][0][x][y] = x * R[0] + y * C[0];
        }
    }

    for (int i = 0; i < H; ++i) {
        for (int j = 0; j < W; ++j) {
            for (int x = 0; x < 2; ++x) {
                for (int y = 0; y < 2; ++y) {
                    ll cost = dp[i][j][x][y];
                    if (cost == INF) continue;

                    // 右へ移動
                    if (j + 1 < W) {
                        int ny = y ^ (A[i][j] - '0')
                                   ^ (A[i][j + 1] - '0');

                        dp[i][j + 1][x][ny] = min(
                            dp[i][j + 1][x][ny],
                            cost + ny * C[j + 1]
                        );
                    }

                    // 下へ移動
                    if (i + 1 < H) {
                        int nx = x ^ (A[i][j] - '0')
                                   ^ (A[i + 1][j] - '0');

                        dp[i + 1][j][nx][y] = min(
                            dp[i + 1][j][nx][y],
                            cost + nx * R[i + 1]
                        );
                    }
                }
            }
        }
    }

    ll ans = INF;
    for (int x = 0; x < 2; ++x) {
        for (int y = 0; y < 2; ++y) {
            ans = min(ans, dp[H - 1][W - 1][x][y]);
        }
    }

    cout << ans << '\n';
}
```

この実装は入力例1で `9`、入力例2で `125` となることを確認しています。

計算量は、各マスについて4状態から高々2方向へ遷移するため、

\[
\boxed{\text{時間 }O(HW),\qquad\text{空間 }O(HW)}
\]

です。DP 配列は最大で約128 MiBです。

費用は最大で \(4\times 10^{12}\) 程度になり得るため、`long long` を使用します。

## 5\. この問題から学べる典型

### 典型① XOR による反転操作の線形化

反転操作を含む問題では、0/1 の反転を XOR で表すと条件が非常に扱いやすくなります。

本問の

\[
B_{i,j}=A_{i,j}\oplus x_i\oplus y_j
\]

はその典型例です。

一般に、XOR の方程式

\[
u\oplus v=d
\]

では、一方の変数が決まれば他方は

\[
v=u\oplus d
\]

と一意に決まります。

この性質によって、多数の反転操作の選択を、局所的な関係式に置き換えられることがあります。

特に、対象が2色である、操作が反転である、複数の操作の効果が重なる、といった条件が見えたら、XOR や mod 2 の方程式を考える価値があります。

また、本問の隣接マスの条件では、共通する行または列の変数が相殺されました。

これはより一般的な **制約の式から共通変数を消去して、局所的な関係を取り出す** という考察手法です。

### 典型② 経路を作りながら決定を確定させる DP

本問では、本来は行・列すべての反転状態を決める必要があります。

しかし、経路を右下に向かって作るという見方をすると、次に訪れる行・列は必ず未訪問です。

そのため、経路に新しい行・列が登場したタイミングで反転状態を確定させ、費用を払うことができます。

これは、**大域的な決定を、処理順序に沿った局所的な決定へ分解する** という発想です。

他の問題でも、決定対象が多数あるときには、「どの順序なら、各決定を一度だけ行い、後から変更せずに済むか」を考えると DP が見つかることがあります。

ただし、この方針には重要な成立条件があります。

今回、右と下だけでなく左や上にも移動できたとすると、以前訪れた列や行に戻る可能性があります。すると、その行・列の反転状態を既に決めているかどうかを管理する必要が生じ、現在の2ビットだけでは情報が不足します。

本問の移動方向の制限は、単に経路の候補を減らしているだけでなく、**過去の決定を忘れてもよい構造を作っている**のです。

### 典型③ 最適化問題の状態を「未来に必要な情報」で絞る

DP の状態設計で大切なのは、過去の選択をすべて記録することではありません。

異なる2通りの過去の経路が、同じ \((i,j,x,y)\) に到達したとします。

この2通りについて、今後どの方向へ進み、どの行・列を反転する必要があるかは、まったく同じ規則で決まります。

したがって、過去にどの経路を通ったかは、将来の最適化に影響しません。費用が小さい方だけを残せば十分です。

これは DP の状態を設計するための基本原則です。

> 同じ状態に到達した複数の履歴について、その先に可能な選択と追加費用が同一なら、最良の履歴だけを保持すればよい。

本問では、行・列の反転状態が大量にあるにもかかわらず、将来に必要な情報が現在の2ビットに圧縮できることが核心です。

## 6\. 正当性の確認

任意の単色経路と反転方法を考えます。

この経路を始点から順番にたどると、初期状態の4通りのいずれかから出発できます。

右へ進むとき、次のマスの色を等しくするための列の反転状態は前述の XOR の式によって一意に決まります。下へ進む場合も同様です。

したがって、その経路と反転方法は DP の遷移で表現できます。

逆に、DP の各遷移は、移動前後の色が等しくなるように新しい行・列の反転状態を設定しています。また、移動するたびに新しい行か列を訪れるため、過去の決定と矛盾せず、操作費用も重複して数えません。

よって、DP が表す経路は必ず実現可能な単色経路であり、すべての実現可能な解も DP で考慮されます。

各状態で最小費用を保持しているので、終点での最小値が求める答えになります。

## 7\. 復習で定着させたいこと

| 着眼点 | 次に活用するための問い |
|--------|--------|
| XOR による表現 | 反転操作を mod 2 の方程式で表せないか？ |
| 隣接要素の条件 | 共通する変数を打ち消して、局所的な関係式を導けないか？ |
| 単調な移動順序 | 新しい対象が登場した時点で決定を確定できないか？ |
| DP の状態圧縮 | 将来の選択に影響する過去の情報は本当に何か？ |

この問題で最も持ち帰りたいのは、**「行・列をどう反転するか」を直接探索するのではなく、「経路を伸ばすと反転状態がどう決まるか」に視点を変えること**です。

その視点の変化によって、指数個あるように見える操作の組合せが、各マス4状態のシンプルな DP に変わります。
