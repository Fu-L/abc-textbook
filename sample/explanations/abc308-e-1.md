# ABC308 E - MEX 解説

(475 点) (数え上げ) (累積和) (全探索の高速化)

この問題の核心は、**添字の組を直接数える代わりに、値の組ごとにまとめて数える**ことです。

さらに、3 つの添字のうち中央を固定すると、左右の選択を独立に扱えるようになります。この考え方は、文字列の部分列を数える問題などにも広く応用できます。

## 1\. 問題の整理

長さ \(N\) の数列 \(A\) と文字列 \(S\) が与えられます。

- \(A_i\in\{0,1,2\}\)
- \(S_i\in\{\mathrm{M},\mathrm{E},\mathrm{X}\}\)

次の条件を満たす添字の組 \((i,j,k)\) をすべて考えます。

\[
i<j<k,\qquad S_i=\mathrm M,\ S_j=\mathrm E,\ S_k=\mathrm X
\]

それぞれについて \(\operatorname{mex}(A_i,A_j,A_k)\) を計算し、その総和を求めます。

mex は、与えられた値に含まれない最小の非負整数です。

例えば、

\[
\begin{aligned}
\operatorname{mex}(1,1,2)&=0\\
\operatorname{mex}(0,0,2)&=1\\
\operatorname{mex}(0,1,1)&=2\\
\operatorname{mex}(0,1,2)&=3
\end{aligned}
\]

制約は \(N\le 2\times10^5\) です。citeturn494205view0

## 2\. 解法に至る考察

### 2.1 まずは全探索を考える

素直に解くなら、\(i<j<k\) となるすべての組を調べ、文字列が `MEX` なら mex を加算します。

しかし、添字の組は最大で \(O(N^3)\) 個あるため、到底間に合いません。

ここから、何をまとめて計算できるかを考えます。

### 2.2 中央の E を固定する

3 つの添字を一度に決める代わりに、真ん中の \(j\) を固定します。

\(S_j=\mathrm E\) とすると、残りの条件は

- \(i<j\) かつ \(S_i=\mathrm M\)
- \(k>j\) かつ \(S_k=\mathrm X\)

です。

中央の E を固定したときの選び方

重要なのは、**\(j\) が固定されると、左の \(i\) と右の \(k\) を独立に選べる**ことです。

例えば、左側に選べる M が 4 個、右側に選べる X が 5 個あれば、条件を満たす組は \(4\times5=20\) 個です。

ただし、今回は組の個数ではなく mex の総和が必要です。したがって、個数だけではまだ足りません。

### 2.3 添字の違いを無視して、値で分類する

ここで mex の性質に注目します。

\[
\operatorname{mex}(A_i,A_j,A_k)
\]

は、添字 \(i,j,k\) 自体には依存せず、対応する値 \(A_i,A_j,A_k\) だけで決まります。

しかも、\(A_i\) は 0, 1, 2 のいずれかです。

つまり、左側の M を次の 3 種類に分類できます。

\[
L[a]=\#\{i<j\mid S_i=\mathrm M,\ A_i=a\}
\]

同じように、右側の X について

\[
R[b]=\#\{k>j\mid S_k=\mathrm X,\ A_k=b\}
\]

とします。

ここで \(a,b\in\{0,1,2\}\) です。

\(A_i=a,\ A_k=b\) となる組は、独立に選べるので

\[
L[a]\times R[b]
\]

個あります。

そして、これらすべての組で mex は同じ値

\[
\operatorname{mex}(a,A_j,b)
\]

になります。

したがって、中央の \(j\) を固定したときの寄与は、

\[
\boxed{
\sum_{a=0}^{2}\sum_{b=0}^{2}
L[a]R[b]\operatorname{mex}(a,A_j,b)
}
\]

です。

これが解法の中心となる式です。

もともと左と右の添字をすべて列挙する必要がありましたが、今は **\(3\times3=9\) 通りの値の組**を調べるだけで済みます。

## 3\. 具体例で考える

入力例 1 を使います。

```text
N = 4
A = 1 1 0 2
S = M E E X
```

添字と対応づけると次のようになります。

| 添字 | 1 | 2 | 3 | 4 |
|--------|--------|--------|--------|--------|
| S | M | E | E | X |
| A | 1 | 1 | 0 | 2 |

中央の E は \(j=2,3\) の 2 か所です。

**中央に固定する位置**

- j = 2
- j = 3
現在の選択内容は利用できません。

この位置の寄与

両方の E の寄与を合計すると、

\[
0+3=\boxed{3}
\]

となり、サンプルの答えと一致します。

この例では、それぞれの値の候補が 1 個ずつでした。仮に左に値 1 の M が 4 個、右に値 2 の X が 5 個あっても、中央の値が同じなら mex は変わりません。その場合は \(4\times5=20\) 組分をまとめて加算できます。

## 4\. 全体を O(N) で処理する

\(j\) を一つずつ固定するたびに、\(L\) と \(R\) を最初から数えていては \(O(N^2)\) になってしまいます。

そこで、左から右に走査しながら個数を更新します。

最初に、すべての X を値ごとに数えて \(R\) に格納しておきます。\(L\) はすべて 0 で初期化します。

各位置を順に処理します。

1. 現在の文字が `M` なら、対応する値の \(L\) を 1 増やす。
2. 現在の文字が `E` なら、9 通りの \((a,b)\) について寄与を計算する。
3. 現在の文字が `X` なら、対応する値の \(R\) を 1 減らす。

こうすることで、E を処理するときには必ず

- \(L\) は現在位置より左にある M の個数
- \(R\) は現在位置より右にある X の個数

を表しています。

1 文字あたり最大 9 通りの計算しかしないため、全体で \(O(9N)=O(N)\) です。公式解説も中央の E を固定し、左右を値ごとに数える方針です。citeturn675006view0

## 5\. C++23 実装

左右の個数を逐次更新することで、累積和配列を作らずに実装できます。

```cpp

#include <bits/stdc++.h>
using namespace std;

using ll = long long;

int mex(int a, int b, int c) {
    for (int x = 0; x <= 3; ++x) {
        if (x != a && x != b && x != c) return x;
    }
    return 3;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;

    vector<int> A(N);
    for (auto &a : A) cin >> a;

    string S;
    cin >> S;

    array<ll, 3> L{}, R{};

    // 右側の X をすべて数えておく
    for (int i = 0; i < N; ++i) {
        if (S[i] == 'X') {
            ++R[A[i]];
        }
    }

    ll ans = 0;

    for (int i = 0; i < N; ++i) {
        if (S[i] == 'M') {
            ++L[A[i]];
        } else if (S[i] == 'X') {
            --R[A[i]];
        } else {
            // S[i] == 'E'
            for (int a = 0; a < 3; ++a) {
                for (int b = 0; b < 3; ++b) {
                    ans += L[a] * R[b]
                         * mex(a, A[i], b);
                }
            }
        }
    }

    cout << ans << '\n';
}
```

**計算量**

- 時間計算量：\(O(N)\)
- 補助空間計算量：\(O(1)\)（入力の保存を除く）

答えは最大で \(O(N^3)\) となるため、`int` ではなく `long long` を使います。

## 6\. この問題から学べる典型

### 典型① 中央の要素を固定して、左右を独立に数える

3 要素の部分列を数える問題で重要な考え方です。

一般に、

\[
i<j<k
\]

という条件があれば、中央の \(j\) を固定することで

\[
(\text{左側の候補数})\times(\text{右側の候補数})
\]

という積に分解できる可能性があります。

例えば、文字列 `ABACBC` に含まれる部分列 `ABC` の個数を考えます。

中央の B を固定してみます。

- 2 文字目の B：左の A は 1 個、右の C は 2 個なので 2 通り
- 5 文字目の B：左の A は 2 個、右の C は 1 個なので 2 通り

よって合計 4 通りです。

本問はこの典型を拡張したものです。単純に組を数えるのではなく、各組に mex という重みが付いています。それでも、値ごとに分類すれば同じ掛け算が使えます。

**見抜くためのポイント：** 3 要素の順序付きの組を数えるときは、中央を固定すると左右の選択が独立にならないかを考えます。

ただし、\(i\) と \(k\) の間に別の制約（例えば \(A_i+A_k\le T\)）がある場合は、そのまま個数の積にできません。左右の選択が独立であることが重要です。

### 典型② 添字ではなく、答えに影響する情報だけで分類する

この問題では、

\[
\operatorname{mex}(A_i,A_j,A_k)
\]

を求める際に、\(i,j,k\) の具体的な位置は不要です。必要なのは各値だけです。

そこで、たくさんある添字を 0, 1, 2 の 3 種類に圧縮しました。

より一般に、左側の候補が \(p\)、右側の候補が \(q\) 種類に分類でき、それぞれの寄与が種類のみに依存するなら、

\[
\sum_{a=1}^{p}\sum_{b=1}^{q}
L[a]R[b]f(a,b)
\]

という形でまとめて計算できます。

例えば、本問で mex の代わりに

\[
\max(A_i,A_j,A_k)
\]

の総和を求める問題でも、まったく同じ方法が使えます。\(f(a,b)\) を \(\max(a,A_j,b)\) に変更するだけです。

逆に、\(A_i\) が \(10^9\) 以下の任意の整数で、値の種類が大量にあると、この 9 通りの全探索は使えなくなります。代わりに、頻度をさらに集約できる性質がないかを調べる必要があります。

**見抜くためのポイント：** 大量の候補を数え上げるときは、「最終的な寄与が同じ候補を一つのグループにできないか」を考えます。

### 典型③ 前後の集計情報を持ちながら走査する

本問では、現在位置より左の M と右の X の情報が同時に必要でした。

このような場合、典型的には

- 左からの累積和
- 右からの累積和

を前計算します。

しかし、位置を左から順番に処理するだけなら、今回のように両方の情報を更新しながら進めることもできます。

最初に右側の個数をすべて用意し、走査によって右側から要素を取り除き、左側に追加していくわけです。

この方法は、部分列の数え上げに限らず、区間を境界で分割し、左右の情報を組み合わせる問題でも有効です。

## 7\. 復習で押さえたいこと

- **3 つの添字の組を数えるなら、まず中央を固定する**ことを考える。
- 左右の候補を独立に選べるなら、候補数の積で組数を求められる。
- 候補が大量にあっても、答えに影響する情報の種類が少なければ、種類ごとの個数でまとめて計算できる。
- 左右の情報は累積和で前計算するだけでなく、走査しながら更新する方法もある。
- 組の数が \(O(N^3)\) になり得る数え上げでは、オーバーフローに注意する。

この問題は、**「中央を固定する」＋「値ごとの頻度にまとめる」＋「左右の集計を維持する」** という 3 つの考え方を組み合わせた良問です。

特に身につけたいのは、単に \(O(N^3)\) を \(O(N)\) にする実装ではなく、**多数の添字を直接扱わず、答えに必要な情報だけを集約するという発想**です。
