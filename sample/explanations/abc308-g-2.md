# ABC308 G - Minimum Xor Pair Query 解説

<text color="secondary" size="sm">AtCoder Beginner Contest 308 / G問題 / 600点</text>

**この問題の核心は、「XOR が最小となるペアは、値を昇順に並べたときの隣接要素から選べる」という性質です。**

この性質に気づけば、全ペアを管理する必要はありません。`multiset` を2つ用いることで、各クエリを \(O(\log Q)\) で処理できます。

## 1. 問題の整理

整数の多重集合 \(S\) に対して、次の3種類のクエリを処理します。

- `1 x`：\(x\) を1個追加する。
- `2 x`：\(x\) を1個削除する。
- `3`：異なる2要素 \(a,b\) を選んだときの \(a\oplus b\) の最小値を出力する。

制約は \(Q\le 3\times 10^5\)、\(0\le x<2^{30}\) です。同じ値を複数回追加できることに注意してください。

<text color="secondary" size="xs">問題文：<Link url="https://atcoder.jp/contests/abc308/tasks/abc308_g" title="ABC308 G"/></text>

## 2. 初見から解法へ至る考察

### まず、全ペアを調べる方法を考える

集合に \(N\) 個の要素があるとき、全ペアの XOR を計算すれば、\(O(N^2)\) で答えを求められます。

しかし、クエリ数が最大 \(3\times 10^5\) なので、この方法は使えません。

そこで考えたいのは次の問いです。

**最小 XOR を実現するペアには、何か特別な関係があるのではないか？**

### 値をソートして観察する

例えば、集合が

\[
S=\{2,3,10,11\}
\]

だったとします。

全6ペアの XOR を調べてみましょう。

| ペア | XOR | 昇順で隣接？ |
|---|---:|---|
| (2, 3) | 1 | ○ |
| (2, 10) | 8 | × |
| (2, 11) | 9 | × |
| (3, 10) | 9 | ○ |
| (3, 11) | 8 | × |
| (10, 11) | 1 | ○ |

最小値の \(1\) は、どちらも昇順で隣接するペアから得られています。

これは偶然でしょうか？

注目したいのは、例えば \(2<3<10\) について、

\[
2\oplus 10=8,\qquad
2\oplus 3=1,\qquad
3\oplus 10=9
\]

となっていることです。

両端の \(2,10\) を直接選ぶよりも、その間にある \(3\) とどちらかの端を組み合わせたほうが、小さな XOR を得られています。

この現象が常に成立するなら、隣接しないペアを調べる必要はなくなります。

### 重要な性質：間に数があれば、より小さい XOR が存在する

実際に、任意の

\[
x<y<z
\]

について、

\[
\boxed{\min(x\oplus y,\ y\oplus z)<x\oplus z}
\]

が成立します。

この性質が本問の決定的なポイントです。

#### なぜ成立するのか？

XOR の大小を考えるときは、**最上位の異なるビット**に注目するのが有効です。

例えば \(x=3,\ y=5,\ z=6\) なら、

  \(3\oplus6=5\) ですが、\(5\oplus6=3\) なので、途中の \(5\) を使うと XOR が小さくなります。

一般の場合にも同じことが起きます。

\(x\) と \(z\) の最上位の異なるビットを \(k\) 桁目（\(2^k\) の位）とします。

\(x<z\) なので、この桁は \(x\) が \(0\)、\(z\) が \(1\) です。また、それより上位のビットは一致しています。

\(x<y<z\) であることから、\(y\) の上位ビットも両者と一致します。

そこで、\(y\) の \(k\) 桁目に注目します。

- **\(y\) のその桁が \(0\)** なら、\(x\) と \(y\) は \(k\) 桁目以上の全ビットが一致するため、\(x\oplus y<2^k\) です。
- **\(y\) のその桁が \(1\)** なら、同様に \(y\oplus z<2^k\) です。

一方、

\[
x\oplus z\ge 2^k
\]

なので、どちらの場合でも

\[
\min(x\oplus y,\ y\oplus z)
< 2^k
\le x\oplus z
\]

が成立します。

### したがって、隣接するペアだけ見ればよい

多重集合の要素を昇順に

\[
a_1\le a_2\le\cdots\le a_N
\]

と並べます。

\(i<j-1\) かつ \(a_i<a_j\) なら、その間には要素 \(a_{i+1}\) が存在します。先ほどの性質から、ペア \((a_i,a_j)\) より小さい XOR を持つペアが存在します。

また、\(a_i=a_j\) なら、等しい値が連続して並んでいるため、隣接ペアの XOR が \(0\) になります。

したがって、

\[
\boxed{
\min_{1\le i<j\le N}(a_i\oplus a_j)
=
\min_{1\le i<N}(a_i\oplus a_{i+1})
}
\]

です。

調べるべきペアは \(O(N^2)\) 個から **\(N-1\) 個**に減りました。

## 3. 挿入・削除による変化を考える

さらに重要なのは、**要素を1個挿入・削除しても、変化する隣接ペアは高々3個**ということです。

例えば、集合

\[

挿入によって起きたのは、

- \((2,10)\) が隣接しなくなった。
- \((2,3)\) と \((3,10)\) が新たに隣接した。
- \((10,11)\) は変わらない。

という変化だけです。

一般に、\(x\) を挿入する位置の直前・直後の要素を \(l,r\) とすれば、次の更新で十分です。

| 操作 | 候補から削除 | 候補に追加 |
|---|---|---|
| \(x\) を挿入 | \(l\oplus r\) | \(l\oplus x,\ x\oplus r\) |
| \(x\) を削除 | \(l\oplus x,\ x\oplus r\) | \(l\oplus r\) |

ただし、存在しない隣接要素に対応する処理は行いません。

これで、あとは各更新と最小値取得を高速に行えるデータ構造を選ぶだけです。

## 4. アルゴリズム

次の2つの `multiset` を管理します。

- `values`：現在の整数を昇順に保持する。
- `adjacent_xors`：`values` の隣接要素どうしの XOR をすべて保持する。

これにより、クエリ `3` の答えは常に `*adjacent_xors.begin()` です。

挿入・削除時には `values` から前後の要素を \(O(\log Q)\) で見つけ、変化する XOR だけを `adjacent_xors` に反映します。

### C++23 実装

<CodeBlock language="cpp" editable>
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int Q;
    cin >> Q;

    multiset<int> values, adjacent_xors;

    // XOR の候補を1個だけ削除する
    auto erase_xor = [&](int v) {
        auto it = adjacent_xors.find(v);
        adjacent_xors.erase(it);
    };

    while (Q--) {
        int t;
        cin >> t;

        if (t == 1) {
            int x;
            cin >> x;

            auto it = values.insert(x);
            auto l = (it == values.begin()
                      ? values.end() : prev(it));
            auto r = next(it);

            // 挿入前に隣接していたペアを削除
            if (l != values.end() && r != values.end())
                erase_xor(*l ^ *r);

            // 新しく隣接するペアを追加
            if (l != values.end())
                adjacent_xors.insert(*l ^ x);
            if (r != values.end())
                adjacent_xors.insert(x ^ *r);

        } else if (t == 2) {
            int x;
            cin >> x;

            auto it = values.find(x);
            auto l = (it == values.begin()
                      ? values.end() : prev(it));
            auto r = next(it);

            // 削除によって消えるペア
            if (l != values.end())
                erase_xor(*l ^ x);
            if (r != values.end())
                erase_xor(x ^ *r);

            // 削除後に新しく隣接するペア
            if (l != values.end() && r != values.end())
                adjacent_xors.insert(*l ^ *r);

            values.erase(it);

        } else {
            cout << *adjacent_xors.begin() << '\n';
        }
    }
}
</CodeBlock>

この実装は提示されたサンプルとランダムな小規模ケースの全ペア全探索との比較で確認しています。

### 実装上の注意：重複を必ず扱う

本問では整数の重複が許されます。例えば

\[
S=\{5,5,12\}
\]

なら、答えは \(5\oplus 5=0\) です。

したがって、`set` ではなく `multiset` を使います。また、異なる隣接ペアが同じ XOR を持つこともあるため、`adjacent_xors` も `multiset` が必要です。

特に、

```cpp
adjacent_xors.erase(v);
```

とすると、値が `v` の要素をすべて削除してしまいます。必ず `find` でイテレータを取得して1個だけ削除してください。

### 計算量

それぞれの操作は `multiset` の挿入・削除・探索を定数回行うだけです。

- 挿入：\(O(\log Q)\)
- 削除：\(O(\log Q)\)
- 答えの取得：\(O(1)\)

よって、全体の計算量は

\[
\boxed{O(Q\log Q)}
\]

空間計算量は \(O(Q)\) です。

## 5. この問題から学べる典型

### 典型①：最適ペアを隣接要素に限定する

本問で最も重要なのは、全ペアを対象とする最適化を、ソート後の隣接ペアに帰着したことです。

より一般的に、ペアのコストを \(f(x,y)\) としたとき、

\[
x<y<z
\implies
\min(f(x,y),f(y,z))\le f(x,z)
\]

が成立するなら、コストの最小値は隣接ペアだけを調べれば求められます。

この性質があれば、端点の間に要素が存在するペアを、より近いペアに置き換えても最小値を悪化させないからです。

代表例は次の2つです。

| ペアのコスト | 隣接だけでよい理由 |
|---|---|
| \(\lvert x-y\rvert\) | 数直線上の距離は、間にある点との距離より大きい |
| \(x\oplus y\) | 最上位の異なるビットについて、間にある数がどちらかの端と一致する |

ただし、XOR の場合は、数値的な距離が近いほど XOR が小さくなるわけではありません。

例えば、

\[
7\oplus 8=15,\qquad 5\oplus7=2
\]

です。数値の差が小さいペアほど XOR が小さい、という推論は誤りです。

**数値の近さではなく、「間に数があるペアは最適解から除外できる」という構造が本質**です。

この典型を思い出したいのは、集合から2要素を選んで何かを最小化する問題です。全ペアを列挙する前に、ソートして間の要素を利用できないか考える価値があります。

### 典型②：順序つき集合と隣接関係の動的管理

順序つき集合における重要な性質として、要素を1個追加・削除するとき、隣接関係の変化は局所的です。

例えば、昇順に

\[
\cdots,l,r,\cdots
\]

と並んでいるところへ \(x\) を挿入すると、

\[
(l,r)\longrightarrow(l,x),(x,r)
\]

という変化が起きます。

この構造は XOR に限らず、隣接要素から計算される値を動的に管理する問題で広く使えます。

例えば、整数の集合に挿入・削除を行いながら、次の値を求める問題にも同じ仕組みを使えます。

\[
\max_i(a_{i+1}-a_i)
\]

この場合も `multiset` で隣接差を管理すれば、最大値を高速に取得できます。

一般的な設計パターンは、

\[
\boxed{
\text{順序つき集合}
+
\text{隣接ペアの情報を保持するデータ構造}
}
\]

です。

`std::multiset` では、挿入位置や削除対象の前後をイテレータで取得できるため、このパターンを簡潔に実装できます。

### 典型③：XOR の大小比較は最上位ビットから考える

XOR を扱う問題では、二進数の最上位ビットに注目すると、大小関係を証明しやすいことがあります。

特に、2つの数が初めて異なる桁を \(k\) とすると、

\[
x\oplus y\ge2^k
\]

が成立します。

一方、その桁を含めて上位ビットが一致する2数の XOR は \(2^k\) 未満です。

この明確な境界を使えば、下位ビットの複雑な振る舞いを詳しく調べる必要がありません。

本問で必要だったのも、「XOR の具体的な値を比較する」ことではなく、「一方が \(2^k\) 未満、もう一方が \(2^k\) 以上になる」と示すことでした。

この発想は、Binary Trie、最小 XOR ペア、最大 XOR ペア、XOR に関する貪欲法などでも重要です。

## 6. 復習で定着させたいこと

- **全ペアの最小化を見たら、ソート後の隣接ペアに限定できないか検討する。** そのためには、間にある要素を使って改善できる性質を探す。
- **XOR の大小比較では、最上位の異なるビットを固定する。** \(2^k\) を境界にすると、大小関係が明確になる場合がある。
- **順序つき集合への1要素の挿入・削除は、隣接関係を局所的にしか変えない。** 隣接ペアに関する情報は、前後の要素だけを使って更新できる。
- **多重集合を扱う際は重複に注意する。** 要素自体の重複と、隣接ペアから計算される値の重複を区別して管理する。

本問は、XOR のビット構造から最適解の候補を絞る考察と、順序つき集合で隣接関係を動的に更新する典型が組み合わさった問題です。

特に復習する価値が高いのは、単に「最小 XOR は隣接ペアから選べる」と覚えるのではなく、**なぜ任意の非隣接ペアを除外できるのかを、最上位の異なるビットから自力で説明できるようにすること**です。
