# ABC308 Ex - Make Q 解説

AtCoder Beginner Contest 308 / Ex / 625点 / 制限時間 4秒

この問題の核心は、**「サイクルに1本の枝を付ける」という構造を、枝の候補を固定した最小サイクル問題へ帰着すること**です。

さらに、枝の候補は各頂点についてコストが小さい3本だけ考えれば十分です。これにより、最短路木を利用して全体を \(O(N^3)\) で解けます。

公式解説とは少し異なりますが、見通しのよい別解を中心に説明します。citeturn688877view0citeturn688877view2

## 1\. 問題の整理

正の重みを持つ単純無向グラフから、次のような部分グラフを選び、その辺の重みの総和を最小化します。

青い部分が単純サイクル、橙色がサイクルの外へ伸びる1本の辺（尾）

サイクルに属し、かつ尾の端点でもある頂点を \(u\)、尾のもう一方の端点を \(v\) とします。

求めたいものは

\[
\min_{\substack{(u,v)\in E\\v\notin C,\ u\in C}}
\left(w(u,v)+w(C)\right)
\]

です。ここで \(C\) は単純サイクル、\(w(C)\) はその辺の重みの合計です。

制約は \(N\le 300\)、\(M\le N(N-1)/2\) です。\(O(N^3)\) 程度を目標にできる一方、全サイクルの列挙は現実的ではありません。citeturn345364view0

## 2\. 解法に至る考察

### 2.1. 尾を固定すると、残りは何になるか？

まず、この図形を特徴づける要素のうち、どこを固定すれば問題が簡単になるか考えます。

サイクル自体を固定しようとすると、候補が指数個存在します。一方、尾はただの1辺なので、こちらを固定する方が自然です。

尾を \((u,v)\) と固定すると、\(v\) はサイクルに含まれてはいけません。

したがって、**頂点 \(v\) を削除したグラフで、頂点 \(u\) を通る最小重みの単純サイクルを求めればよい**ことになります。

これを \(f(u,v)\) と書くと、

\[
\text{候補値}=w(u,v)+f(u,v)
\]

です。

例えば入力例1では、尾を \((3,1)\) とすると、頂点1を削除したグラフで

\[
3\to2\to4\to5\to3
\]

というサイクルを選べます。

その重みは \(4+3+2+1=10\)、尾の重みは \(5\) なので、合計 \(15\) です。

問題はここからです。

尾の候補は最大 \(M=O(N^2)\) 個あります。最小サイクルを毎回 \(O(N^2)\) で求めるとしても、全体で \(O(N^4)\) となってしまいます。

そこで、尾の候補を減らせないか考えます。

### 2.2. 各頂点から出る最安の3辺だけを考える

ある最適解のサイクル \(C\) と、尾の付け根 \(u\) に注目します。

サイクルにおいて、\(u\) に接続する辺はちょうど2本あります。

残りの辺の中から、最も安いものを尾に使えればよさそうです。

つまり、\(u\) に接続する辺をコスト昇順に並べれば、**先頭3本のうち少なくとも1本は、サイクルの2辺とは異なる**ことがわかります。

ただし、その3本目の行き先がサイクルの内部にある場合が問題です。その辺は尾ではなく、サイクルの弦になってしまいます。

ここで、重みがすべて正という条件が効きます。

### 2.3. サイクル内部へ向かう辺は、むしろ改善につながる

次の小さい例を考えます。

破線が弦 (1,3)、左へ伸びる辺 (1,5) が元の尾

元のQはサイクル \(1\to2\to3\to4\to1\) と尾 \((1,5)\) で、コストは

\[
2+2+2+2+6=14
\]

です。

しかし、頂点1から伸びる辺 \((1,3)\) は尾よりずっと安いにもかかわらず、サイクル内に向かっています。

そこで弦を利用してサイクルを作り直します。

新しいサイクルを \(1\to2\to3\to1\) とし、辺 \((1,4)\) を尾にすると、

\[
2+2+1+2=7
\]

でQを作れます。

つまり、安い弦があった場合、元のサイクルを短くして、**元のQよりさらに安いQを作れてしまう**のです。

一般に、弦 \((u,x)\) を加えると、元のサイクルは2本の \(u\)\-\(x\) パスに分かれます。片方のパスと弦を新しいサイクルにし、もう片方のパスの \(u\) 側の最初の辺を尾にすればよいです。

元の尾より高くない弦を用いた場合、少なくとも元のサイクルの辺を1本以上捨てるため、総コストは必ず小さくなります。

したがって、最適解において、サイクルの2辺以外で最も安い辺がサイクル内部に向かうことはありません。

以上より、次の性質が成立します。

**重要な結論：最適なQの尾は、付け根の頂点から出るコスト最小の3辺のいずれかに限定できる。**

各頂点について3本だけ調べればよいので、尾の候補は高々 \(3N\) 個です。

これで、各候補を \(O(N^2)\) で処理できれば全体 \(O(N^3)\) が達成できます。

## 3\. 指定された頂点を通る最小サイクルを求める

ここがもう一つの重要な典型です。

頂点 \(r\) を通る最小コストの単純サイクルを、\(O(N^2)\) で求めます。

### 3.1. サイクルを2本のパスと1辺に分解する

サイクルを1辺 \((x,y)\) で切ると、残りは \(r\) から \(x\)、\(r\) から \(y\) への2本のパスとして捉えられます。

仮にこれらが頂点 \(r\) 以外で交わらないなら、

\[
d(r,x)+d(r,y)+w(x,y)
\]

という形でサイクルのコストを計算できます。

ここで \(d\) は最短距離です。

ただし、単に最短経路を2本取ると、途中で同じ頂点を通り、単純サイクルにならない可能性があります。

必要なのは、**2本の最短経路が根 \(r\) 以外では交わらない**という保証です。

### 3.2. 最短路木の根直下で枝分かれさせる

頂点 \(r\) を始点とする Dijkstra 法で、最短路木 \(T\) を構築します。

そして各頂点 \(x\ne r\) に対して、最短路木上で \(r\) から \(x\) へ向かうとき、最初に通る頂点を \(g[x]\) と定義します。

\(g[r]=r\) としておきます。

最短路木の異なる枝に属する x, y を非木辺で結ぶ

\(g[x]\ne g[y]\) なら、\(r\to x\) と \(r\to y\) の木上の経路は、根 \(r\) 以外では交わりません。

そこに辺 \((x,y)\) を加えると、ちょうど1つの単純サイクルができます。

したがって、最短路木の辺を除いたすべての辺 \((x,y)\) について、

\[
g[x]\ne g[y]
\]

を満たすものだけを調べ、

\[
\boxed{
\min\left(d[x]+d[y]+w(x,y)\right)
}
\]

を計算すればよいです。

注意点として、最短路木そのものの辺は使えません。特に根から直接伸びる木辺を許してしまうと、同じ辺を往復する長さ2の閉路を誤って数えてしまいます。

### 3.3. 入力例1で具体的に追う

先ほどの例に戻り、尾を \((3,1)\) に固定して頂点1を削除します。

頂点3を根とする最短路木は次のようになります。

最短距離と所属する枝は次の通りです。

| 頂点 \(x\) | \(d[x]\) | \(g[x]\) |
|--------|--------|--------|
| 3 | 0 | 3 |
| 5 | 1 | 5 |
| 4 | 3 | 5 |
| 2 | 4 | 2 |

非木辺 \((4,2)\) は、異なる枝を結んでいます。

したがって、

\[
d[4]+w(4,2)+d[2]=3+3+4=10
\]

というサイクルが得られます。

その実体は

\[
3\to5\to4\to2\to3
\]

です。

尾のコスト5を加えて、答えの15が求まります。

### 3.4. なぜこれで本当に最小サイクルが見つかるのか？

候補として得られるものが単純サイクルであることは、異なる枝の最短路が根以外で交わらないことからわかります。

逆方向も確認しましょう。

任意の \(r\) を通る単純サイクル \(C\) を考えます。

サイクルは根 \(r\) から出発して、最後に \(r\) に戻るため、最短路木における異なる枝の間を移動するか、根と同じ枝に属する頂点を非木辺で直接結ぶ必要があります。

したがって、\(C\) には、異なるラベル \(g[x]\ne g[y]\) を結ぶ非木辺 \((x,y)\) が少なくとも1本存在します。

この辺について、\(C\) 上の \(r\) から \(x,y\) への短い方の経路の長さをそれぞれ \(l_x,l_y\) とすると、

\[
l_x+l_y+w(x,y)\le w(C)
\]

です。また、Dijkstra で求めた距離は

\[
d[x]\le l_x,\qquad d[y]\le l_y
\]

なので、

\[
d[x]+d[y]+w(x,y)\le w(C)
\]

が成立します。

つまり、どんなサイクル \(C\) に対しても、それ以下のコストの候補が見つかります。一方、各候補は実際に単純サイクルを構成するので、求めた最小値は最小サイクルのコストと一致します。

密グラフ向けの Dijkstra 法は \(O(N^2)\)、全辺の確認も \(O(N^2)\) です。

よって、**指定頂点を通る最小サイクルは \(O(N^2)\) で求められます。**

## 4\. アルゴリズム全体

ここまでの考察を統合します。

各頂点 \(u\) を尾の付け根として考え、\(u\) に接続する辺をコスト昇順に並べます。次数が3未満ならQの付け根になれないため無視します。

その先頭3辺について、もう一方の端点を \(v\) とし、頂点 \(v\) を削除したグラフで \(u\) を通る最小サイクルを求めます。見つかれば、そのコストに \(w(u,v)\) を加え、答えを更新します。

最後までサイクルが見つからなければ \(-1\) を出力します。

## 5\. C++23 実装

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;
constexpr ll INF = (1LL << 60);

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector w(n, vector<ll>(n, INF));

    for (int i = 0; i < m; ++i) {
        int a, b;
        ll c;
        cin >> a >> b >> c;
        --a, --b;
        w[a][b] = w[b][a] = c;
    }

    // banned を削除したグラフで、
    // root を通る最小サイクルのコストを求める。
    auto shortest_cycle = [&](int root, int banned) -> ll {
        vector<ll> dist(n, INF);
        vector<int> par(n, -1), branch(n, -1);
        vector<bool> used(n, false);

        used[banned] = true;
        dist[root] = 0;
        branch[root] = root;

        // O(N^2) Dijkstra
        for (int t = 0; t < n; ++t) {
            int v = -1;

            for (int j = 0; j < n; ++j) {
                if (!used[j] &&
                    (v == -1 || dist[j] < dist[v])) {
                    v = j;
                }
            }

            if (v == -1 || dist[v] == INF) break;
            used[v] = true;

            for (int to = 0; to < n; ++to) {
                if (used[to] || w[v][to] == INF) continue;

                if (dist[to] > dist[v] + w[v][to]) {
                    dist[to] = dist[v] + w[v][to];
                    par[to] = v;

                    branch[to] =
                        (v == root ? to : branch[v]);
                }
            }
        }

        ll best = INF;

        // 異なる枝を結ぶ非木辺を列挙
        for (int x = 0; x < n; ++x) {
            if (dist[x] == INF) continue;

            for (int y = x + 1; y < n; ++y) {
                if (dist[y] == INF || w[x][y] == INF)
                    continue;

                if (branch[x] == branch[y]) continue;

                // 最短路木の辺は使えない
                if (par[x] == y || par[y] == x) continue;

                best = min(
                    best, dist[x] + dist[y] + w[x][y]
                );
            }
        }

        return best;
    };

    ll ans = INF;

    for (int u = 0; u < n; ++u) {
        vector<pair<ll, int>> edges;

        for (int v = 0; v < n; ++v) {
            if (w[u][v] != INF) {
                edges.emplace_back(w[u][v], v);
            }
        }

        if (edges.size() < 3) continue;

        sort(edges.begin(), edges.end());

        // 安い方から3本だけ尾の候補にする
        for (int k = 0; k < 3; ++k) {
            auto [cost, v] = edges[k];

            ll cycle = shortest_cycle(u, v);

            if (cycle != INF) {
                ans = min(ans, cost + cycle);
            }
        }
    }

    cout << (ans == INF ? -1 : ans) << '\n';
}
```

サンプル3件に対して、出力が `15`, `-1`, `78154` となることを確認しています。

### 計算量

各頂点について最大3回、\(O(N^2)\) の最小サイクル探索を行います。

\[
O(3N\cdot N^2)=\boxed{O(N^3)}
\]

空間計算量は隣接行列を含めて \(O(N^2)\) です。

## 6\. この問題から学べる典型

### 典型①：局所的な次数制約で、最適解の候補を絞る

本問で特に価値が高いのは、全辺の列挙を \(O(N^2)\) から \(O(N)\) に減らした考察です。

最適解の尾の付け根では、サイクルに使われる辺が2本しかありません。この「必ず使われる2本」という制約から、残りの最安辺は、全体で見ても安い方から3本以内に入ると考えられます。

これは、最適解の一部分を固定したとき、その他の選択肢として何番目までの候補を考えればよいか、という一般的な着眼点です。

例えば、ある頂点において、最適解が高々 \(k\) 本の辺を特定の用途に使うなら、それ以外から追加の1辺を選ぶとき、安い方から \(k+1\) 本を考えれば候補が存在する、という発想につながります。

ただし本問では、安い辺がサイクル内へ向かう可能性がありました。そこで、その場合にはより安い解へ作り替えられることを示す必要がありました。

**候補数の削減は、単に安い順に取るという貪欲法ではなく、最適解の交換・変形によって正当化することが重要です。**

### 典型②：最短路木の異なる枝を結んでサイクルを作る

この技法は、指定頂点を通る最小サイクルを求める問題で利用できます。

最短路木からサイクルを構成するとき、問題になるのは2本の経路の重複です。そこで、最短路木の根直下の枝ごとに頂点を分類し、異なる枝を結ぶ非木辺だけを考えます。

これは単なる最短距離の計算ではなく、**最短路木という構造を使って、2本の経路が内部頂点を共有しないことを保証する**テクニックです。

同じ発想は、2本の内部頂点素な経路を使ったサイクル構成や、最短路木に非木辺を追加する問題でも役立ちます。

なお、指定頂点を通る最小サイクルと、グラフ全体での最小サイクルは別問題です。今回の根直下の枝という区別は、指定頂点を必ず通るために使っています。

### 典型③：複雑な図形は、構成要素を固定して単純な問題へ帰着する

Qを直接列挙するのではなく、尾を固定することで、残りの構造を最小サイクルという既知の問題に変えられました。

今回の流れは

\[
\text{Qの最適化}
\longrightarrow
\text{尾を固定}
\longrightarrow
\text{指定頂点を通る最小サイクル}
\]

です。

このような問題では、全体の構造を一度に決定するよりも、少数の辺や頂点を固定して、残りを最短路・木・マッチングなどの標準問題に帰着できないか考えると有効です。

## 7\. 復習ポイント

- **最適解の候補削減**：ある頂点で2本の辺が既に使われているなら、追加の1本は最安の3本から探せないか考える。
- **交換による正当化**：安い候補が条件を満たさない場合、その候補を使って元の最適解を改善できないか考える。
- **最短路木とサイクル**：指定頂点を根にした最短路木で、異なる枝を結ぶ非木辺を調べると、根を通る単純サイクルを構成できる。
- **実装上の注意**：最短路木の辺をサイクルを閉じる辺として使わない。特に根に接続する木辺の除外を忘れない。

この問題で最も持ち帰りたいのは、**「尾の候補は3本で十分」という局所的な候補削減と、「最短路木の異なる枝」という構造的な捉え方の組み合わせ**です。両方とも、より難しいグラフ最適化問題に応用できる考え方です。
