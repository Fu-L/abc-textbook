# ABC264 G - String Fair 解説

<text color="secondary" size="sm">AtCoder Beginner Contest 264 · G問題 · 600点</text>

この問題の核心は、**文字列の評価を「1文字追加したときの得点変化」に分解し、文字列全体ではなく末尾2文字だけを状態として持つこと**です。

そうすると、無限に長い文字列を考える最適化問題が、頂点数 \(O(26^2)\) の重み付き有向グラフ上の問題に変わります。あとは Bellman–Ford 法で最大スコアと正閉路を調べれば解けます。

## 1. 問題を整理する

英小文字からなる空でない文字列 \(S\) を自由に作ります。

長さ3以下の文字列 \(T_i\) と得点 \(P_i\) が与えられており、\(S\) の美しさは

\[
\operatorname{score}(S)
=\sum_{i=1}^{N}P_i\cdot \operatorname{occ}(T_i,S)
\]

で定義されます。ここで \(\operatorname{occ}(T_i,S)\) は \(T_i\) が連続部分文字列として現れる回数です。

求めるのは美しさの最大値です。ただし、いくらでも大きくできる場合は `Infinity` と出力します。

重要な制約は次のとおりです。

- \(1\le N\le 18278\)
- \(1\le |T_i|\le 3\)
- \(-10^9\le P_i\le 10^9\)
- 作る文字列 \(S\) の長さには上限がない

特に注目すべきなのは、**評価に使う部分文字列の長さが最大3**という条件です。

## 2. 考察：文字列を1文字ずつ作る

### 文字を追加すると、どの得点が変化するか？

文字列全体の得点を直接評価するよりも、末尾に文字を追加したときの変化を調べる方が扱いやすそうです。

例として、次の得点規則を考えます。指定されていない文字列の得点は0です。

| 文字列 | 得点 |
|---|---:|
| `a` | -2 |
| `ab` | +5 |
| `bab` | +7 |

現在の文字列が `ba` で、末尾に `b` を追加して `bab` にするとします。

追加によって新しく登場する部分文字列は、末尾で終わる次の3つです。

    <table-row><table-cell>`bab`（長さ3）</table-cell><table-cell align="end">+7</table-cell></table-row>
    <table-row><table-cell>**得点の増加量**</table-cell><table-cell align="end">**+12**</table-cell></table-row>

このとき、すでに存在していた部分文字列の出現回数は変わりません。増えるのは、新しい末尾で終わる部分文字列の分だけです。

一般に、指定されていない文字列の得点を \(P(T)=0\) と定義すると、文字列の末尾2文字が \(a,b\) のとき、新しく \(c\) を追加することによる得点の増加量は

\[
\boxed{\Delta(a,b,c)=P(c)+P(bc)+P(abc)}
\]

になります。

### 末尾2文字だけ覚えておけばよい

ここで重要なことに気づきます。

例えば、現在の文字列が

- `xyzaba`
- `caba`
- `aba`

のどれであっても、次に `c` を追加するときに新しく生じる部分文字列は、`c`、`ac`、`bac` で共通です。

つまり、これまでに獲得した得点を別に管理すれば、次の文字による得点変化を決めるために必要なのは **末尾2文字だけ**です。

文字列全体を状態とすれば候補は無限にありますが、末尾2文字だけなら高々 \(26^2=676\) 通りです。

これは、状態を圧縮できることを示しています。

## 3. 末尾2文字を頂点とするグラフに変換する

状態 `ab` を頂点と考えます。

ここに `c` を追加すると、末尾2文字は `bc` に変わります。

よって、次の有向辺を張ります。

\[
\boxed{ab\xrightarrow{\,P(c)+P(bc)+P(abc)\,}bc}
\]

辺の重みは、その1文字を追加して獲得する得点です。

例えば、先ほどの規則では次の遷移ができます。

### 最初の2文字はどう扱うか？

まだ文字を1文字も選んでいないときには、末尾2文字が存在しません。

ここはダミー文字 `$` を用意して、初期状態を `$$` とすると簡潔に扱えます。

`$` を含む文字列の得点は0と定義します。

\]

\[
E=729\times26=18954
\]

これで、元の問題は次のグラフ問題になりました。

> 始点 `$$` から出発し、少なくとも1本の辺を通る walk（頂点や辺を繰り返してよい経路）の重みの合計を最大化する。上限がなければ `Infinity` とする。

## 4. 無限に長い文字列と正閉路

ここまでで有限個の頂点を持つグラフになりましたが、作る文字列の長さには制限がないので、同じ頂点を何度も訪問できます。

そこで、閉路に注目します。

### 得点が正の閉路を繰り返せば Infinity

入力例1では、

\[
P(a)=-5,\quad P(ab)=10,\quad P(ba)=-20
\]

です。

次の閉路を考えます。

`za` から始めて `bza` を追加すると、再び `za` に戻ります。その間に得られる得点は

\[
10+0-5=5>0
\]

です。

したがって、この閉路を \(k\) 回繰り返せば、得点を \(5k\) ずつ増やせます。

これが `abz` の繰り返しで美しさをいくらでも大きくできる理由です。

一般に、**始点から到達可能な正の重みの閉路が存在することと、答えが `Infinity` になることは同値**です。

正閉路が存在しなければ、閉路を通っても得点は増えません。したがって、閉路を取り除いても得点が減らないので、最大値を与える walk として単純パスを選べます。

つまり、正閉路がない場合は、長さ高々 \(V-1\) のパスだけ考えれば十分です。

## 5. Bellman–Ford 法で解く

### 最大得点の DP を考える

頂点 \(v\) に対して、

\[
dp_k[v]
\]

を「始点 `$$` から出発し、**高々 \(k\) 本の辺を通って**頂点 \(v\) に到達する場合の最大得点」と定義します。

初期条件は

\[
dp_0[v]=
\begin{cases}
0 & (v=\texttt{\$\$})\\
-\infty & (\text{otherwise})
\end{cases}
\]

です。

辺 \(u\to v\) の重みを \(w(u,v)\) とすると、

\[
dp_{k+1}[v]
=
\max\left(
dp_k[v],
\max_{u\to v}(dp_k[u]+w(u,v))
\right)
\]

と更新できます。

これは Bellman–Ford 法で最短距離を求めるときの緩和操作を、最大化に置き換えたものです。

### なぜ \(V\) 回の更新で十分なのか

正閉路が存在しない場合、最適な経路から閉路を取り除けます。

頂点数が \(V\) のグラフにおける単純パスの長さは高々 \(V-1\) なので、

\[
dp_{V-1}[v]
\]

が各頂点までの最大得点を表します。

一方、\(V\) 回目の更新でも改善が発生したら、どうでしょうか。

改善が発生するということは、\(V\) 本の辺を通ることで、より短い経路では実現できない得点を獲得できたということです。

しかし、\(V\) 本の辺を通る walk には必ず閉路が含まれます。もしその閉路の重みが0以下なら、それを取り除いても得点は減らず、長さも短くできます。

したがって、改善が発生するためには正閉路が必要です。

逆に、到達可能な正閉路が存在すれば、繰り返すことで得点を無制限に増やせるため、更新は収束しません。

よって、

\[
\boxed{
V\text{ 回目に改善が発生}
\iff
\text{Infinity}
}
\]

が成り立ちます。

### 空文字列を答えに含めない

この問題で注意したいのが、**空文字列は禁止されている**ことです。

例えば入力例3では、全ての英小文字の得点が \(-1\) です。

長さ1なら得点は \(-1\)、長さ2なら \(-2\)、というように、文字列が長いほど得点は小さくなります。

よって答えは \(-1\) です。

ところが、初期状態 `$$` の得点は0なので、これを答えの候補に含めると誤って0を出力してしまいます。

初期状態 `$$` に戻る辺は存在しないため、**最終的に `$$` 以外の頂点について最大値を取れば、必ず1文字以上追加した経路だけを評価できます。**

## 6. C++23 実装

状態数は小さいので、辺を明示的に保持せず、末尾2文字と追加する文字を3重ループで列挙します。

<CodeBlock language="cpp" editable>
#include <bits/stdc++.h>
using namespace std;

using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;

    constexpr int A = 26;
    constexpr int K = 27; // 英小文字26種類 + ダミー文字
    constexpr int V = K * K;
    constexpr int START = A * K + A;
    constexpr ll NEG = -(1LL << 60);

    ll p1[K] = {};
    ll p2[K][K] = {};
    ll p3[K][K][K] = {};

    for (int i = 0; i < N; ++i) {
        string s;
        ll p;
        cin >> s >> p;

        if (s.size() == 1) {
            p1[s[0] - 'a'] = p;
        } else if (s.size() == 2) {
            p2[s[0] - 'a'][s[1] - 'a'] = p;
        } else {
            p3[s[0] - 'a'][s[1] - 'a'][s[2] - 'a'] = p;
        }
    }

    // dp[v]: 始点から現在の辺数以内で
    //        頂点 v に到達する最大得点
    vector<ll> dp(V, NEG);
    dp[START] = 0;

    for (int iteration = 0; iteration < V; ++iteration) {
        vector<ll> ndp = dp;
        bool updated = false;

        for (int a = 0; a < K; ++a) {
            for (int b = 0; b < K; ++b) {
                int u = a * K + b;
                if (dp[u] == NEG) continue;

                for (int c = 0; c < A; ++c) {
                    int v = b * K + c;

                    ll gain = p1[c]
                            + p2[b][c]
                            + p3[a][b][c];

                    ll cand = dp[u] + gain;

                    if (cand > ndp[v]) {
                        ndp[v] = cand;
                        updated = true;
                    }
                }
            }
        }

        // V 回目も更新されるなら正閉路が存在
        if (iteration == V - 1 && updated) {
            cout << "Infinity\n";
            return 0;
        }

        dp.swap(ndp);

        if (!updated) break;
    }

    // 空文字列に対応する始点は除外
    ll ans = NEG;
    for (int v = 0; v < V; ++v) {
        if (v != START) {
            ans = max(ans, dp[v]);
        }
    }

    cout << ans << '\n';
}
</CodeBlock>

この実装では、更新前後の配列を分けています。そのため、\(k\) 回目の更新後の `dp` が「高々 \(k\) 本の辺を使う場合の最大得点」を正確に表します。

また、各得点が最大 \(10^9\) で、辺の重みは最大 \(3\times10^9\) となるため、`long long` を使用します。

### 計算量

頂点数と辺数は

\[
V=27^2=729,\qquad E=27^2\times26=18954
\]

です。

Bellman–Ford 法の計算量は \(O(VE)\) なので、

\[
O(27^4\times26)
\]

となります。緩和を試みる回数は最大約1382万回で、十分高速です。

得点配列を含めた空間計算量は \(O(27^3)\) です。

## 7. この問題から学べる典型

### 典型①：局所的な得点を状態付きグラフに変換する

この問題で最も重要な技法です。

文字列全体が評価対象なので、一見すると巨大な状態を管理しなければならないように思えます。しかし、得点を確定させるタイミングを「文字を1つ追加した瞬間」に変えると、過去の情報のうち必要なものが限定されます。

今回、長さ3以下の部分文字列だけが得点に影響するので、**次の遷移に必要なのは直前2文字だけ**でした。

一般に、長さ高々 \(L\) の部分文字列ごとに加点する問題なら、末尾 \(L-1\) 文字を状態として管理できます。

文字集合のサイズを \(K\) とすると、状態数は高々

\[
O(K^{L-1})
\]

になります。

この考え方は、文字列以外にも応用できます。

例えば数列を左から構築して、隣接3要素 \((a_i,a_{i+1},a_{i+2})\) ごとに得点が決まるなら、やはり直前2要素を覚えれば十分です。

**見抜くための手がかり**は、「追加する要素によって変化する評価が、直近の一定個数の要素だけで決まるか？」という問いです。

この条件が成り立てば、有限個の状態を持つオートマトンやグラフに変換できる可能性があります。

さらに、評価対象の文字列が長さ3以下に限られない場合でも、複数のパターンの出現を数える問題では、Aho–Corasick 法で構築したオートマトンを状態グラフとして利用できることがあります。

### 典型②：長さ無制限の最大化と正閉路

次に重要なのは、**経路の長さに上限がない最適化問題では、閉路が答えを無限大にする可能性がある**という観点です。

重み付き有向グラフ上で、walk の重みの合計を最大化するとき、閉路には次の性質があります。

| 閉路の重み | 繰り返す効果 |
|---|---|
| 正 | 得点が増加する。無限大にできる |
| 0 | 得点は変わらない |
| 負 | 得点が減少する。繰り返す意味がない |

したがって、正閉路の有無を判定することが本質になります。

これは Bellman–Ford 法の負閉路検出を符号反転したものです。

各辺の重み \(w\) を \(-w\) に変えれば、

- 最大得点 → 最短距離
- 正閉路 → 負閉路

という対応ができます。

本問では最大化のまま実装しましたが、重みの符号を反転して通常の Bellman–Ford 法に帰着させても構いません。

なお、一般のグラフでは、正閉路が存在するだけでなく、**始点からその閉路へ到達可能であること**が必要です。到達不能な閉路は最適化に影響しません。

### 典型③：問題を有限化できても、元の制約を保つ

この問題では、状態グラフへの変換によって無限に長い文字列を扱えるようになりました。

しかし、元の問題にあった「文字列は空でない」という条件を忘れると、誤答になります。

このように、DP の初期状態や補助的なダミー状態が、元の問題の有効な解に対応しているとは限りません。

特に最大化問題で、答えが負になり得る場合は、**初期値0を不用意に答えの候補へ含めないこと**が重要です。

## 8. 復習：次の問題で使うために

- **部分文字列の出現回数で得点が決まる**なら、文字を1つ追加したときの得点変化を考える。
- **直近 \(L\) 個の要素だけが次の遷移に影響する**なら、それらを状態として圧縮できないか考える。
- **長さ無制限で得点を最大化する**なら、正閉路によって答えが無限大になる可能性を調べる。
- **最短路・最長路の Bellman–Ford 法**では、\(V\) 回目の緩和による更新が閉路検出につながる。
- **空でない・少なくとも1回操作する**という条件は、初期状態を答えに含めてよいかという実装上の問題に直結する。

本問で最も身につけたいのは、「文字列を自由に作る」という無限の選択肢を持つ問題でも、**得点の変化を局所的に捉えると、有限状態のグラフ問題に落とし込める**という発想です。

公式解説も、この状態グラフへの帰着と Bellman–Ford 法を採用しています。<Cite refs={["turn550093view0","turn364883view0"]}/>
