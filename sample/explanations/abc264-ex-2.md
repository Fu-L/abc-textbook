# ABC264 Ex - Perfect Binary Tree 解説

<text color="secondary" size="sm">難易度：600点 / 主要テーマ：木DP、頂点追加、差分更新、完全二分木のサイズ制約</text>

**問題：** <Link url="https://atcoder.jp/contests/abc264/tasks/abc264_h" title="AtCoder ABC264 Ex - Perfect Binary Tree"/>
**公式解説：** <Link url="https://atcoder.jp/contests/abc264/editorial/4584" title="公式解説（日本語）"/>

## 1. 問題の整理

\(N\) 頂点の根付き木が与えられます。根は頂点 \(1\) で、各頂点 \(i\) の親 \(P_i\) は必ず \(i\) より小さい番号です。

各 \(k=1,\ldots,N\) について、頂点 \(1,\ldots,k\) から頂点 \(1\) を含む部分集合を選び、その誘導部分グラフが**完全二分木**になる選び方を数えます。

完全二分木とは、すべての内部頂点がちょうど2個の子を持ち、すべての葉が同じ深さにある木です。

頂点数の制約は \(N\le 3\times10^5\) です。

## 2. 解法に至る考察

### 着眼点① 完全二分木の大きさから高さを制限する

まず、完全二分木という強い条件に注目します。

根から葉までの辺数を高さ \(h\) とすると、完全二分木の頂点数は

\[
1+2+4+\cdots+2^h=2^{h+1}-1
\]

です。

| 高さ \(h\) | 必要な頂点数 |
|---:|---:|
| 0 | 1 |
| 1 | 3 |
| 2 | 7 |
| 3 | 15 |
| 10 | 2,047 |
| 17 | 262,143 |
| 18 | 524,287 |

\(N\le300000\) なので、高さ18以上の完全二分木は作れません。

つまり、**答えに寄与する完全二分木の高さは最大17** です。

さらに、選んだ部分グラフは頂点1を根とする木なので、選ばれた頂点の深さは元の木での深さと一致します。

したがって、元の木で深さ18以上にある頂点は、最終的な答えに一切寄与しません。

ここが最初の大きな突破口です。

元の木は深さ \(N-1\) の一本道かもしれませんが、答えに関係する頂点だけを考えると、深さ17までしかありません。

この観察から、

**頂点を1個追加するたびに、その頂点から根まで祖先をたどって更新する**

という方針が現実的になります。更新する祖先は高々18個です。

### 着眼点② 頂点番号順に追加すると、新頂点は必ず葉になる

問題では \(k=1,2,\ldots,N\) について答えを求めるので、頂点を番号順に追加していくことを考えます。

ここで

\[
P_i<i
\]

という制約が重要です。

頂点 \(i\) を追加するとき、親はすでに存在しますが、子はまだ存在しません。なぜなら、すべての子の番号は \(i\) より大きいからです。

そのため、頂点 \(i\) は追加時点で必ず葉です。

そして、頂点 \(i\) を含む新しい完全二分木を考えると、\(i\) はその完全二分木の葉にもなります。

これは何を意味するのでしょうか。

例えば、以下の木を考えます。

頂点5を追加したとき、新しく作れる完全二分木は、頂点2を根とする \(\{2,4,5\}\) です。

- 頂点5を根とするなら、高さ0。
- 頂点2を根とするなら、高さ1。
- 頂点1を根とするなら、高さ2。

一般に、新しい頂点 \(i\) を含む完全二分木の根が祖先 \(v\) なら、その高さは必ず

\[
h=\operatorname{depth}(i)-\operatorname{depth}(v)
\]

です。

**各祖先について更新すべきDP状態が1個だけに決まる** ことがわかります。

通常の木DPでは高さごとに複数の状態を更新しますが、本問では新頂点が葉であるため、祖先を1段上がるごとに高さを1増やすだけで済みます。

### 着眼点③ 木DPを考えるが、毎回すべてを計算し直さない

ある頂点 \(v\) を根とする、高さ \(h\) の完全二分木の数を

\[
dp[v][h]
\]

と定義します。ここでは、現在までに追加された頂点だけを使用するものとします。

高さ0の場合は頂点 \(v\) だけを選ぶので、追加済みなら

\[
dp[v][0]=1
\]

です。

高さ \(h\ge1\) の完全二分木を作るには、\(v\) の子から異なる2頂点 \(a,b\) を選び、それぞれを根とする高さ \(h-1\) の完全二分木を選べばよいです。

したがって、

\[
dp[v][h]
=
\sum_{\substack{\{a,b\}\subseteq \operatorname{ch}(v)\\a\ne b}}
dp[a][h-1]dp[b][h-1]
\]

となります。和は子の unordered pair に対して取ります。

これが基本となる木DPです。

ただし、頂点が追加されるたびに、この式を全部計算し直していては間に合いません。

そこで、**新しく増えた完全二分木だけを差分として伝播させる** ことを考えます。

### 着眼点④ 片方の子の増加分に、もう片方の子の総和を掛ける

まずは高さ1の完全二分木を考えましょう。

頂点1に、子として頂点2、3、4が順番に追加される場合です。

頂点4を追加する直前、頂点1を根とする高さ1の完全二分木は

\[
\{1,2,3\}
\]

の1通りです。

頂点4を追加すると、

\[
\{1,2,4\},\quad \{1,3,4\}
\]

の2通りが新たに増えます。

注目したいのは、頂点4を使うことを固定すると、もう片方の子は既存の頂点2、3から自由に選べるということです。

高さが大きい場合も同様です。

頂点 \(p\) の子 \(v\) を根とする、高さ \(h\) の完全二分木が \(\Delta\) 通り増えたとします。

これを使って頂点 \(p\) を根とする高さ \(h+1\) の完全二分木を作るには、もう片方として \(v\) 以外の子を根とする高さ \(h\) の完全二分木を選べばよいです。

そこで、子についてのDPの総和

\[
S[p][h]=\sum_{w\in\operatorname{ch}(p)}dp[w][h]
\]

も管理しておきます。

すると、新しく増える完全二分木の数は

\[
\boxed{
\Delta'
=
\Delta\bigl(S[p][h]-dp[v][h]\bigr)
}
\]

です。

右辺の \(S\) と \(dp\) は、今回の差分を反映する前の値です。

\(dp[v][h]\) を引いているのは、左右の部分木が同じ子 \(v\) に属してはいけないからです。

これで、ある頂点のDPが変化したとき、その親のDPがどれだけ変化するかを \(O(1)\) で計算できるようになりました。

## 3. 差分更新のアルゴリズム

頂点 \(i\) を追加したとしましょう。

まず、新しい頂点を根とする高さ0の完全二分木が1通り増えます。

\[
\Delta=1
\]

この増加分を親に伝え、さらにその親へ、と根に到達するまで繰り返します。

各段階で、現在の頂点を \(v\)、その親を \(p\)、現在の高さを \(h\) とします。

\[
\begin{aligned}
\Delta'&=\Delta(S[p][h]-dp[v][h]),\\
dp[v][h]&\gets dp[v][h]+\Delta,\\
S[p][h]&\gets S[p][h]+\Delta.
\end{aligned}
\]

更新後は \(v\gets p,\ h\gets h+1,\ \Delta\gets\Delta'\) として続けます。

親が存在しない、つまり根に達したら、その時点の \(\Delta\) が今回新しく増えた、頂点1を根とする完全二分木の数です。これを答えに加算します。

### 具体例：頂点5の追加を追ってみる

先ほどの5頂点の木を使います。

```text
       1
      / \
     2   3
    / \
   4   5 ← 今回追加
```

頂点5の追加前には、頂点2を根とする高さ1の完全二分木はまだありません。

頂点5を追加すると、以下のように差分が伝わります。

| 現在の頂点 \(v\) | 高さ \(h\) | 増加分 \(\Delta\) | 次の増加分 |
|---|---:|---:|---:|
| 5 | 0 | 1 | \(1\times1=1\) |
| 2 | 1 | 1 | \(1\times0=0\) |
| 1 | 2 | 0 | 終了 |

最初の段階では、頂点5の兄弟である頂点4を選べるため、頂点2を根とする高さ1の完全二分木が1通り増えます。

次の段階では、頂点1のもう片方の子である頂点3を根とする、高さ1の完全二分木が必要です。

しかし頂点3には子がないため、そのような部分木は0通りです。

したがって、頂点1を根とする高さ2の完全二分木は増えません。

このように、**新しく追加された頂点を含む完全二分木を、葉から根に向かって組み立てながら数えている** と理解すると、更新式の意味がわかりやすくなります。

## 4. C++23実装

以下は公式解説の方針を、答えを差分で直接管理する形に整理した実装です。

<CodeBlock language="cpp" editable>
#include <bits/stdc++.h>
using namespace std;

constexpr int MOD = 998244353;
constexpr int H = 18;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;

    vector<int> parent(N + 1, 0);
    vector<int> depth(N + 1, 0);

    for (int i = 2; i <= N; i++) {
        cin >> parent[i];
    }

    // dp[v][h]: v を根とする高さ h の完全二分木の数
    // sum[v][h]: v の子 w に対する dp[w][h] の総和
    vector<array<int, H>> dp(N + 1);
    vector<array<int, H>> sum(N + 1);

    int answer = 0;

    for (int i = 1; i <= N; i++) {
        if (i > 1) {
            depth[i] = depth[parent[i]] + 1;
        }

        // 高さ18以上の完全二分木は存在しない
        if (depth[i] < H) {
            int delta = 1;

            // 新頂点から根まで差分を伝播
            for (int v = i, h = 0; v != 0;
                 v = parent[v], h++) {

                int p = parent[v];
                int next = 0;

                if (p != 0) {
                    // v 以外の子で作れる部分木の数
                    int other = sum[p][h] - dp[v][h];
                    if (other < 0) other += MOD;

                    next = 1LL * delta * other % MOD;
                }

                // 現在の頂点のDPを更新
                dp[v][h] = (dp[v][h] + delta) % MOD;

                if (p != 0) {
                    sum[p][h] = (sum[p][h] + delta) % MOD;
                } else {
                    // 根のDPの増加分が答えの増加分
                    answer = (answer + delta) % MOD;
                }

                delta = next;
            }
        }

        cout << answer << '\n';
    }

    return 0;
}
</CodeBlock>

<text color="secondary" size="xs">入力例1・4、および小規模ランダムケース150件の全探索との比較で出力を確認済みです。</text>

### 計算量

1回の頂点追加につき、深さが18以上なら更新不要で、そうでなければ高々18頂点を訪問します。各頂点の更新は \(O(1)\) です。

したがって、全体では

\[
\boxed{O(N\log N)\text{ 時間},\quad O(N\log N)\text{ 空間}}
\]

となります。

本問の制約では、高さ方向の配列サイズを18に固定しているため、実際の計算量は時間・空間ともに \(O(18N)\) です。

## 5. 正しさの核心

このアルゴリズムが正しい理由は、追加した頂点 \(i\) を含む新しい完全二分木と、差分更新によって数える構造が1対1に対応することです。

頂点 \(i\) は追加時点で葉なので、これを含む完全二分木の根を \(v\) と固定すれば、高さは \(v\) と \(i\) の距離に決まります。

その完全二分木において、\(v\) から \(i\) へ向かう子の部分木は、今回追加された \(i\) を含む新しい完全二分木です。一方、もう片方の子の部分木は \(i\) を含まず、追加前から存在します。

よって、前者の増加分 \(\Delta\) と、後者の選び方の総数を掛けることで、新しく増えた完全二分木を過不足なく数えられます。

また、各完全二分木は2つの子を集合として選ぶため、同じ構造を左右の入れ替えによって二重に数えることもありません。

これを新頂点から根まで繰り返せば、追加した頂点を含む、頂点1を根とするすべての完全二分木をちょうど1回ずつ数えられます。

既存の完全二分木は変化せず、新しく増えるものは必ず頂点 \(i\) を含むため、差分を累積した値が各 \(k\) の答えになります。

## 6. この問題から学ぶ重要な典型

### 典型① 構造のサイズ制約から、有効な深さを制限する

この問題で最も早く気づきたいのは、完全二分木の頂点数が高さに対して指数的に増えることです。

一般に、各内部頂点がちょうど \(b\) 個の子を持つ完全 \(b\) 分木なら、高さ \(h\) の頂点数は

\[
1+b+b^2+\cdots+b^h
=\frac{b^{h+1}-1}{b-1}
\]

となります。

したがって、頂点数が \(N\) 以下という制約から、あり得る高さは \(O(\log_b N)\) です。

この典型は、元のグラフや木の深さが大きくても、**問題が要求する構造自体が大きくなる速度** に注目するというものです。

特に、すべての分岐先が必要な構造、各段階でサイズが倍増する構造、再帰的に同じ条件を課す構造などを見たときには、その構造を実現する最小サイズを計算してみる価値があります。

ただし、通常の二分木では子を1個だけ持つ頂点も存在できるため、高さを \(O(\log N)\) に抑えることはできません。本問では「完全」という条件が不可欠です。

### 典型② オフラインの木DPを、頂点追加によるオンラインDPへ変える

完成した木に対する木DPが書けても、すべての \(k\) に対して計算し直すのは非効率です。

本問では \(P_i<i\) なので、頂点を番号順に追加すると、親から子へと構造が増えていきます。

このような状況では、完成した木に対するDPを考えた後、**1頂点追加されたとき、どの状態がどれだけ変化するか** を考えるとよいです。

今回の場合、追加頂点は必ず葉であるため、新しい完全二分木における根の位置が決まれば、高さも決まります。

その結果、各祖先のDP状態が1つずつしか変わりません。

もし頂点の追加順序が任意だったら、新しく追加される頂点に既存の子が存在する可能性があり、この単純な差分伝播は成り立ちません。

つまり、本問の \(P_i<i\) は単なる入力形式上の条件ではなく、更新を単純化できる重要な構造です。

### 典型③ 2つの異なる子を選ぶDPと、総和による差分更新

もう一つの重要な典型は、

\[
F(a_1,\ldots,a_m)=\sum_{i<j}a_i a_j
\]

という形の値を管理することです。

これは2次の基本対称多項式と呼ばれます。

ある1要素 \(a_t\) が \(\Delta\) 増加した場合、変化する項は \(a_t\) を含む項だけです。

そのため、

\[
\begin{aligned}
F(\ldots,a_t+\Delta,\ldots)-F(\ldots,a_t,\ldots)
&=\sum_{j\ne t}\Delta a_j\\
&=\Delta\left(\sum_j a_j-a_t\right).
\end{aligned}
\]

つまり、

\[
\boxed{\Delta F=\Delta(S-a_t)}
\]

です。

本問では \(a_t=dp[v][h]\)、\(S=S[p][h]\) に対応しています。

この形の典型を見抜くポイントは、**異なる2つの要素を選んで積を足し合わせており、そのうち1要素だけが更新される** ことです。

このような更新式は、2つの異なる子を選ぶ木DPだけでなく、異なるグループ間でペアを作る数え上げにも応用できます。

ここで単純に総和の二乗を使おうとすると、

\[
\frac{S^2-\sum_i a_i^2}{2}
\]

という式も得られます。しかし、1要素だけが変化するオンライン更新では、差分公式のほうが必要な情報が少なく、直接的です。

なお、もし毎回変更される要素が1個だけでなく複数個なら、差分同士を組み合わせる項も発生します。その場合は更新順序や重複カウントに注意が必要です。

## 7. 復習：次の問題で思い出したいこと

- **完全・均等・指数的に増える構造** が登場したら、必要な最小サイズから高さや状態数を制限できないか調べる。
- **親が子より先に登場する** ときは、新頂点が葉である性質を利用して、祖先方向への差分伝播を考える。
- **木DPを繰り返し求める問題** では、毎回再計算する代わりに、どの状態だけが変化するかを考える。
- **異なる2要素を選んで積を合計する式** では、総和を保持することで1要素の変更を \(O(1)\) で反映できる場合がある。
- 差分を使うときは、今回の新しい要素を二重に選ばないように、更新前の情報と更新後の情報を明確に区別する。

この問題の一番重要な発想は、木DPの式そのものよりも、**「高さが小さい」「新頂点は葉」「したがって祖先ごとに1状態だけ更新すればよい」** という3つの観察を組み合わせることです。

この構造を発見できれば、残りは子のDPの総和を管理する差分更新として自然に導けます。
