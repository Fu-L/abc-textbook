# ABC308 F - Vouchers 解説

<row align="center" gap={2} wrap="wrap">
  <badge color="info">500点</badge>
  <badge>貪欲法</badge>
  <badge>優先度付きキュー</badge>
  <badge>ソート</badge>
</row>

この問題は、**選択肢の少ない商品から処理し、その時点で使えるクーポンのうち割引額が最大のものを選ぶ**という貪欲法で解けます。

重要なのは、なぜ価格の安い商品から処理するのか、そしてなぜその場で最大の割引を選んでよいのか、という2点です。

## 1. 問題の整理

\(N\) 個の商品と \(M\) 枚のクーポンがあります。

商品 \(i\) の価格は \(P_i\) 円、クーポン \(j\) は価格が \(L_j\) 円以上の商品に使用でき、\(D_j\) 円割引されます。

各商品には高々1枚、各クーポンも高々1回しか使えません。

すべての商品を購入する金額を最小化します。制約は \(N,M\leq 2\times 10^5\) です。<Cite ref="turn440422view0"/>

クーポンを使わない場合の合計金額は

\[
S=\sum_{i=1}^{N}P_i
\]

で固定です。したがって、求めたいのは

\[
\boxed{S-\text{クーポンによる割引額の最大合計}}
\]

です。

ここから、**クーポンをどの商品に割り当てれば割引額の合計が最大になるか**という問題として考えられます。

## 2. 考察：どの順番で商品を処理するか

### 価格の高い商品から考えると？

まず、価格の高い商品から処理し、使用可能なクーポンのうち割引額が最大のものを使う方法を考えます。

例えば、次のケースです。

商品価格：\(5,10\)

| クーポン | 使用可能な価格 | 割引額 |
|---|---:|---:|
| A | 5円以上 | 5円 |
| B | 10円以上 | 4円 |

価格の高い10円の商品から考えると、AとBの両方が使えるため、割引額の大きいAを使いたくなります。

すると5円の商品にはBを使えず、割引額の合計は5円です。

しかし、Aを5円の商品、Bを10円の商品に使えば、合計9円の割引になります。

この例から、価格の高い商品は多くのクーポンを使えるため、そこで自由度の高いクーポンを消費してしまうと、安い商品に使えるクーポンがなくなる可能性がある、とわかります。

### 安い商品ほど選択肢が少ない

クーポンが使える条件は

\[
L_j\leq P_i
\]

です。

ここで \(P_a\leq P_b\) であれば、商品 \(a\) に使えるクーポンは、必ず商品 \(b\) にも使えます。

つまり、

\[
\{\text{商品 }a\text{ に使えるクーポン}\}
\subseteq
\{\text{商品 }b\text{ に使えるクーポン}\}
\]

という包含関係があります。

安い商品に使えるクーポンなら、後に登場する高い商品でも使えるので、割り当てを入れ替える余地があります。

## 3. 使用可能なクーポンのうち、どれを選ぶか

価格の安い商品から処理すると決めました。

次は、その時点で使用可能なクーポンが複数ある場合、どれを選ぶべきかを考えます。

例えば、商品価格が \(5,10\) で、クーポンが次の3枚の場合です。

| クーポン | 使用可能な価格 | 割引額 |
|---|---:|---:|
| A | 5円以上 | 5円 |
| B | 5円以上 | 2円 |
| C | 10円以上 | 10円 |

5円の商品にはAとBが使えます。

ここでBを選ぶと、10円の商品にCを使うことになり、割引額の合計は \(2+10=12\) 円です。

一方、Aを選べば、割引額の合計は \(5+10=15\) 円になります。

このように、その時点で使用可能なクーポンの中では、割引額が最大のものを選ぶのがよさそうです。

### なぜ最大の割引を選んでよいのか

この貪欲選択は、交換論法で正当化できます。

商品を価格の昇順で処理しているとします。現在の商品に使用可能な未使用クーポンのうち、割引額が最大のものを \(A\) とします。

このとき、今までの貪欲な選択と一致する最適解が存在すると仮定し、現在の商品に注目します。

最適解が現在の商品にAを使用していない場合、次のいずれかです。

**場合1：最適解でAが使われていない**

現在の商品に使用されているクーポンをAに置き換えます。

Aは使用可能な中で割引額が最大なので、割引額の合計は減りません。現在の商品にクーポンが使われていなければ、そのままAを追加できます。

**場合2：最適解でAが後の商品に使われている**

現在の商品に使われているクーポンを \(B\) とし、AとBを入れ替えます。

もし現在の商品にクーポンが使われていなければ、Aを現在の商品に移動するだけです。

重要なのは、商品を価格の昇順に処理していることです。

Bが現在の商品に使えるなら、価格が同じかそれ以上の後の商品にも必ず使えます。

したがって、交換後もすべての使用条件を満たし、割引額の合計も変わりません。

以上から、どちらの場合でも、最適性を失わずに現在の商品へAを割り当てられます。

使用可能なクーポンがない場合は定価購入するしかありません。

よって、各商品で次の操作を繰り返す貪欲法は正しいとわかります。

\[
\boxed{\text{安い商品から、使用可能な最大割引クーポンを使う}}
\]

## 4. アルゴリズムへの落とし込み

各商品について、使用可能なクーポンをすべて調べると \(O(NM)\) になり、間に合いません。

ここで、商品を価格の昇順に見ると、**使用可能になるクーポンは増えるだけで、再び使用不可になることはない**点に注目します。

そこで、クーポンも使用条件 \(L_j\) の昇順にソートしておきます。

商品価格を \(p\) とすると、まだ追加していないクーポンのうち \(L_j\leq p\) を満たすものを、割引額 \(D_j\) として優先度付きキューに追加します。

このキューを最大ヒープにすれば、最大の割引額を \(O(\log M)\) で取り出せます。

## 5. C++23 実装

<CodeBlock language="cpp" editable>
#include <bits/stdc++.h>
using namespace std;

using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N, M;
    cin >> N >> M;

    vector<ll> P(N);
    for (auto &p : P) cin >> p;

    vector<ll> L(M), D(M);
    for (auto &l : L) cin >> l;
    for (auto &d : D) cin >> d;

    // (使用条件, 割引額)
    vector<pair<ll, ll>> coupons(M);
    for (int i = 0; i < M; ++i) {
        coupons[i] = {L[i], D[i]};
    }

    sort(P.begin(), P.end());
    sort(coupons.begin(), coupons.end());

    priority_queue<ll> pq;
    ll ans = accumulate(P.begin(), P.end(), 0LL);

    int j = 0;
    for (ll p : P) {
        // 現在の商品に使えるクーポンを追加
        while (j < M && coupons[j].first <= p) {
            pq.push(coupons[j].second);
            ++j;
        }

        // 最も割引額の大きいクーポンを使用
        if (!pq.empty()) {
            ans -= pq.top();
            pq.pop();
        }
    }

    cout << ans << '\n';
}
</CodeBlock>

`priority_queue` はデフォルトで最大ヒープです。

また、商品の合計金額は最大 \(2\times10^{14}\) 円になるので、答えには `long long` を使う必要があります。

### 計算量

商品のソートが \(O(N\log N)\)、クーポンのソートが \(O(M\log M)\) です。

各クーポンは高々1回ヒープに追加され、高々1回取り出されるため、ヒープ操作の合計は \(O(M\log M+N\log M)\) 以下です。

全体では

\[
\boxed{O((N+M)\log(N+M))}
\]

となり、制約内で十分高速です。

## 6. この問題から学べる典型

### 典型①：候補集合が包含関係にあるときの貪欲法

この問題の本質は、単に商品を安い順に処理することではありません。

**ある対象に割り当て可能な選択肢が、別の対象の選択肢に完全に含まれている**という構造が重要です。

一般に、対象 \(i\) に割り当てられる候補の集合を \(C_i\) として、

\[
C_1\subseteq C_2\subseteq \cdots\subseteq C_N
\]

が成り立つとします。

この場合、候補の少ない対象から割り当てると、後の対象ほど割り当ての自由度が高くなります。

特に、今回のように候補ごとの得点が割り当て先によらず一定であり、候補を1回だけ使用する場合は、現在使える最大得点の候補を割り当てる貪欲法を交換論法で正当化できます。

この構造は、例えば締切付きの仕事や、ある条件以上の資源を必要とするタスクへの割り当て問題にも現れます。

ただし、選択肢の少ない順に割り当てれば常に最適になるわけではありません。**割り当て先を交換できること、交換しても目的関数が悪化しないこと**の確認が必要です。

本問では、価格の昇順による候補集合の包含関係と、割引額が商品によらず \(D_j\) で一定であることが、これらを保証しています。

### 典型②：ソート + 優先度付きキューによる候補管理

もう一つの重要な典型は、条件を満たした候補が順次追加されていく状況で、最良の候補を効率よく取り出す方法です。

例えば、「時刻 \(t\) までに解禁された仕事のうち、報酬が最大のものを選ぶ」という問題を考えます。

仕事を解禁時刻の昇順にソートしておけば、時刻が進むたびに新しく解禁される仕事だけをヒープへ追加できます。

すでに解禁されている仕事を毎回調べ直す必要はありません。

本問では次のように対応します。

| 一般的な構造 | 本問 |
|---|---|
| 時間や基準値 | 商品価格 \(P_i\) |
| 候補が追加される条件 | \(L_j\leq P_i\) |
| 候補の優先度 | 割引額 \(D_j\) |
| 候補を選ぶ操作 | 最大割引のクーポンを使う |

ここで大切なのは、**候補の追加条件と、候補の優先順位が別の値で決まる**ことです。

\(L_j\) でソートすることで候補の追加を効率化し、\(D_j\) をヒープで管理することで最適な候補の選択を効率化しています。

この「追加する順序はソート、選ぶ順序はヒープ」という役割分担は、さまざまな貪欲法で再利用できます。

また、もし候補が後から使用不可になる場合、今回のようにヒープへ追加するだけでは対応できません。候補の削除や有効期限の管理が必要になります。したがって、候補の有効性が単調に変化するかどうかも重要な判断材料です。

## 7. 復習：次の問題で思い出したいこと

- **割り当ての問題では、対象ごとの候補集合を比較する。** 候補集合に包含関係があれば、自由度の低い順に処理する方針を検討する。
- **貪欲選択の正しさは交換論法で考える。** 別の最適解から、目的関数を悪化させずに貪欲な選択へ変更できるか確かめる。
- **候補が単調に追加され、最大値・最小値を繰り返し選ぶなら、ソート + 優先度付きキューを検討する。**
- **追加条件と優先順位を区別する。** 本問では追加条件は \(L_j\)、優先順位は \(D_j\) である。

この問題で特に身につけたいのは、「安い順に処理する」という解法そのものよりも、**候補集合の包含関係を発見し、それを交換論法につなげる考え方**です。
