# ABC308 G - Minimum Xor Pair Query 解説

<text color="secondary" size="sm">AtCoder Beginner Contest 308 / G問題 / 600点</text>

**この問題の核心は、「XOR が最小となるペアは、値を昇順に並べたときの隣接要素から選べる」という性質です。**

この性質に気づけば、全ペアを管理する必要はありません。`multiset` を2つ用いることで、各クエリを \(O(\log Q)\) で処理できます。

## 1. 問題の整理

整数の多重集合 \(S\) に対して、次の3種類のクエリを処理します。

- `1 x`：\(x\) を1個追加する。
- `2 x`：\(x\) を1個削除する。
- `3`：異なる2要素 \(a,b\) を選んだときの \(a\oplus b\) の最小値を出力する。

制約は \(Q\le 3\times 10^5\)、\(0\le x<2^{30}\) です。同じ値を複数回追加できることに注意してください。

<text color="secondary" size="xs">問題文：<Link url="https://atcoder.jp/contests/abc308/tasks/abc308_g" title="ABC308 G"/></text>

## 2. 初見から解法へ至る考察

### まず、全ペアを調べる方法を考える

集合に \(N\) 個の要素があるとき、全ペアの XOR を計算すれば、\(O(N^2)\) で答えを求められます。

しかし、クエリ数が最大 \(3\times 10^5\) なので、この方法は使えません。

そこで考えたいのは次の問いです。

**最小 XOR を実現するペアには、何か特別な関係があるのではないか？**

### 値をソートして観察する

例えば、集合が

\[
S=\{2,3,10,11\}
\]

だったとします。

全6ペアの XOR を調べてみましょう。

| ペア | XOR | 昇順で隣接？ |
|---|---:|---|
| (2, 3) | 1 | ○ |
| (2, 10) | 8 | × |
| (2, 11) | 9 | × |
| (3, 10) | 9 | ○ |
| (3, 11) | 8 | × |
| (10, 11) | 1 | ○ |

最小値の \(1\) は、どちらも昇順で隣接するペアから得られています。

これは偶然でしょうか？

注目したいのは、例えば \(2<3<10\) について、

\[
2\oplus 10=8,\qquad
2\oplus 3=1,\qquad
3\oplus 10=9
\]

となっていることです。

両端の \(2,10\) を直接選ぶよりも、その間にある \(3\) とどちらかの端を組み合わせたほうが、小さな XOR を得られています。

この現象が常に成立するなら、隣接しないペアを調べる必要はなくなります。

### 重要な性質：間に数があれば、より小さい XOR が存在する

実際に、任意の

\[
x<y<z
\]

について、

\[
\boxed{\min(x\oplus y,\ y\oplus z)<x\oplus z}
\]

が成立します。

この性質が本問の決定的なポイントです。

#### なぜ成立するのか？

XOR の大小を考えるときは、**最上位の異なるビット**に注目するのが有効です。

例えば \(x=3,\ y=5,\ z=6\) なら、

    <text color="secondary" size="xs">最上位の相違ビットに注目</text>
  </row>

      <text x="10" y={35+i*35} fontSize="14" fontWeight="500" fill="currentColor">{item.label}</text>

  </svg>
  \(3\oplus6=5\) ですが、\(5\oplus6=3\) なので、途中の \(5\) を使うと XOR が小さくなります。
</box>

一般の場合にも同じことが起きます。

\(x\) と \(z\) の最上位の異なるビットを \(k\) 桁目（\(2^k\) の位）とします。

\(x<z\) なので、この桁は \(x\) が \(0\)、\(z\) が \(1\) です。また、それより上位のビットは一致しています。

\(x<y<z\) であることから、\(y\) の上位ビットも両者と一致します。

そこで、\(y\) の \(k\) 桁目に注目します。

- **\(y\) のその桁が \(0\)** なら、\(x\) と \(y\) は \(k\) 桁目以上の全ビットが一致するため、\(x\oplus y<2^k\) です。
- **\(y\) のその桁が \(1\)** なら、同様に \(y\oplus z<2^k\) です。

一方、

\[
x\oplus z\ge 2^k
\]

なので、どちらの場合でも

\[
\min(x\oplus y,\ y\oplus z)
< 2^k
\le x\oplus z
\]

が成立します。

### したがって、隣接するペアだけ見ればよい

多重集合の要素を昇順に

\[
a_1\le a_2\le\cdots\le a_N
\]

と並べます。

\(i<j-1\) かつ \(a_i<a_j\) なら、その間には要素 \(a_{i+1}\) が存在します。先ほどの性質から、ペア \((a_i,a_j)\) より小さい XOR を持つペアが存在します。

また、\(a_i=a_j\) なら、等しい値が連続して並んでいるため、隣接ペアの XOR が \(0\) になります。

したがって、

\[
\boxed{
\min_{1\le i<j\le N}(a_i\oplus a_j)
=
\min_{1\le i<N}(a_i\oplus a_{i+1})
}
\]

です。

調べるべきペアは \(O(N^2)\) 個から **\(N-1\) 個**に減りました。

## 3. 挿入・削除による変化を考える

ここまでで、昇順に隣接するペアだけを管理すればよいと分かりました。

さらに重要なのは、**要素を1個挿入・削除しても、変化する隣接ペアは高々3個**ということです。

例えば、集合

\[
S=\{2,10,11\}
\]

を考えます。

挿入によって起きたのは、

- \((2,10)\) が隣接しなくなった。
- \((2,3)\) と \((3,10)\) が新たに隣接した。
- \((10,11)\) は変わらない。

という変化だけです。

一般に、\(x\) を挿入する位置の直前・直後の要素を \(l,r\) とすれば、次の更新で十分です。

| 操作 | 候補から削除 | 候補に追加 |
|---|---|---|
| \(x\) を挿入 | \(l\oplus r\) | \(l\oplus x,\ x\oplus r\) |
| \(x\) を削除 | \(l\oplus x,\ x\oplus r\) | \(l\oplus r\) |

ただし、存在しない隣接要素に対応する処理は行いません。

これで、あとは各更新と最小値取得を高速に行えるデータ構造を選ぶだけです。
