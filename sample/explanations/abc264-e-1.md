# ABC264 E - Blackout 2 解説

(AtCoder Beginner Contest 264) (E問題・500点)

**この問題の核心は、「辺の削除」を「辺の追加」に変換することです。** さらに、複数の発電所を1つの頂点にまとめると、通常の Union-Find だけで簡潔に解けます。

本問から学びたい典型は、次の2つです。

- **操作を逆順に処理するオフラインアルゴリズム**
- **複数の特殊な頂点を1つにまとめるグラフの変換**

参照：url問題文https://atcoder.jp/contests/abc264/tasks/abc264_e・url公式解説https://atcoder.jp/contests/abc264/editorial/4597

## 1\. 問題を整理する

\(N\) 個の都市と \(M\) 個の発電所があり、それらを結ぶ \(E\) 本の電線があります。

都市から電線を辿ってどれか1つの発電所に到達できれば、その都市には電気が通っています。

このグラフに対して、指定された電線を1本ずつ削除する操作が \(Q\) 回行われます。各操作の直後に、電気が通っている都市の数を求めます。

主な制約は

\[
N+M\le 2\times10^5,\quad Q\le E\le 5\times10^5
\]

です。

まず、グラフの用語に置き換えましょう。

**電気が通っている都市とは、発電所を少なくとも1つ含む連結成分に所属する都市のこと**です。

つまり、この問題は「辺が削除されるグラフで、特定の頂点集合に到達できる頂点の数を管理する問題」と考えられます。

## 2\. 考察：なぜ逆順に処理するのか？

### まずは素朴に考える

電線が1本切れるたびに、発電所を始点とする BFS や DFS を実行すれば、電気が通っている都市をすべて数えられます。

しかし、各回 \(O(N+M+E)\) かかるので、全体では

\[
O(Q(N+M+E))
\]

となり、間に合いません。

ここで、毎回グラフ全体を探索せずに済む方法を考えます。

### Union-Find は使えそうだが……

連結成分を管理すると聞いて、Union-Find（DSU）が思い浮かびます。

Union-Find は、主に以下の処理を高速に行えます。

- 2頂点が同じ連結成分に属するか判定する
- 2つの連結成分を統合する
- 連結成分のサイズを求める

ところが、Union-Find が得意なのは**辺を追加する操作**です。

辺を削除したときには、連結成分が2つ以上に分裂する可能性があります。通常の Union-Find は、統合した成分を分割することができません。

ここで、問題の条件にもう一度注目します。

> 削除される電線はすべて最初から与えられており、一度削除された電線は復活しない。

ということは、すべての削除操作が終わった状態を最初に構築できます。

そこから時間を逆に進めれば、電線の削除は電線の追加に変わります。

### 小さい例で確認する

都市 \(1,2,3,4\)、発電所 \(P,Q\) があり、次のように繋がっているとします。

各時点で電気が通っている都市の数は、順に \(4,2,0\) です。

逆順なら、連結成分は統合されることはあっても、分裂することはありません。

これなら Union-Find がそのまま使えそうです。

**典型的な発想は、「辺の削除を扱いづらいなら、操作を逆転して辺の追加にできないか？」と考えることです。**

## 3\. 電気が通っている都市の数をどう管理するか？

逆順処理によって Union-Find が使えることはわかりました。

次は、Union-Find で何を管理すればよいかを考えます。

### 方法1：各連結成分に発電所があるか管理する

素直に考えると、各連結成分について、次の情報を持たせれば十分です。

- 発電所が1つ以上あるか
- 所属する都市の数

2つの連結成分を統合するとき、電気が通っている都市の数が増えるのは、片方にだけ発電所がある場合です。

例えば、発電所がある連結成分と、都市が3つだけ含まれる連結成分を統合すると、新たに3都市に電気が通ります。

一方、どちらにも発電所がある場合や、どちらにもない場合は、電気が通る都市の数は変わりません。

この方法でも十分高速に解けます。実際、公式解説もこの方針です。citeturn953036view0

ただし、この問題ではもう一段階簡単にできます。

### 方法2：すべての発電所を1つにまとめる

問題の条件を確認します。

> 都市から、どれか1つの発電所に到達できればよい。

**どの発電所に到達できるかは関係ありません。**

そこで、すべての発電所を1つの特殊な頂点 \(P\) にまとめてしまいましょう。

例えば、次のグラフを考えます。

変換前

変換後

実際には別々の発電所でも、「電気が通っているか」の判定では同一視してよい。

変換前、都市1と都市2は別の連結成分です。しかし、どちらも発電所に到達できています。

変換後は同じ連結成分になりますが、電気が通っている都市は変わりません。

この変換が正しい理由は、都市から特殊頂点 \(P\) に到達できることと、元のグラフでいずれかの発電所に到達できることが同値だからです。

変換後のグラフで \(P\) に至る経路があれば、その経路で最初に \(P\) に到達する部分は、元のグラフでもいずれかの発電所まで辿れる経路に対応します。

したがって、発電所を統合しても答えは変わりません。

### Union-Find のサイズだけで答えが出せる

変換後の頂点は、\(N\) 個の都市と1個の特殊頂点 \(P\) だけです。

電気が通っている都市は、ちょうど \(P\) と同じ連結成分に属する都市です。

そのため、

\[
\boxed{\text{答え}=\operatorname{size}(P)-1}
\]

となります。

\(-1\) は、連結成分のサイズに含まれる特殊頂点 \(P\) 自身を除くためです。

これで、各連結成分に発電所の有無を記録したり、統合時に場合分けしたりする必要がなくなりました。

## 4\. アルゴリズム

以上を組み合わせると、解法は非常に簡潔です。

**初期化**

最初に、削除される \(Q\) 本の電線をすべて除いたグラフを作ります。

都市は \(0,\ldots,N-1\) とし、すべての発電所を頂点 \(N\) に置き換えます。

削除されない辺だけを Union-Find に追加します。

**逆順の処理**

\(i=Q-1,Q-2,\ldots,0\) の順に、次を実行します。

1. `ans[i] = uf.size(N) - 1` とする。
2. 削除されていた電線 \(X_i\) を Union-Find に追加する。

ここで重要なのは、**電線を復旧する前に答えを記録すること**です。

その時点のグラフは、元の問題でちょうど \(i\) 番目のイベントが終わった状態に対応しています。

最後に `ans` を先頭から出力すれば完成です。

## 5\. C++23 実装

AtCoder Library の `dsu` を使います。

```cpp

#include <bits/stdc++.h>
#include <atcoder/dsu>
using namespace std;
using namespace atcoder;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N, M, E;
    cin >> N >> M >> E;

    vector<int> U(E), V(E);

    // 都市: 0, ..., N-1
    // 発電所: すべて N にまとめる
    auto convert = [&](int x) {
        --x;
        return min(x, N);
    };

    for (int i = 0; i < E; ++i) {
        int u, v;
        cin >> u >> v;
        U[i] = convert(u);
        V[i] = convert(v);
    }

    int Q;
    cin >> Q;

    vector<int> X(Q);
    vector<bool> removed(E, false);

    for (int i = 0; i < Q; ++i) {
        cin >> X[i];
        --X[i];
        removed[X[i]] = true;
    }

    dsu uf(N + 1);

    // すべてのイベントが終わった状態
    for (int i = 0; i < E; ++i) {
        if (!removed[i]) {
            uf.merge(U[i], V[i]);
        }
    }

    vector<int> ans(Q);

    // 操作を逆順に処理
    for (int i = Q - 1; i >= 0; --i) {
        ans[i] = uf.size(N) - 1;

        int e = X[i];
        uf.merge(U[e], V[e]);
    }

    for (int x : ans) {
        cout << x << '\n';
    }
}
```

### 計算量

Union-Find の1回の操作は、償却 \(O(\alpha(N+1))\) 時間です。ここで \(\alpha\) は逆アッカーマン関数で、実用上ほぼ定数です。

初期化で最大 \(E\) 回、逆順処理で \(Q\) 回の `merge` を行うので、

\[
\boxed{O((N+M+E+Q)\alpha(N+1))}
\]

時間、\(O(N+E+Q)\) 空間で解けます。

## 6\. この問題から学べる典型

### 典型①：削除操作を逆順の追加操作に変換する

これは本問で最も重要な典型です。

動的なグラフでは、辺の追加と削除は対称に見えて、アルゴリズム的には大きな違いがあります。

Union-Find は連結成分の統合を効率的に処理できますが、分割はできません。

そこで、**削除のみが行われ、しかも削除内容が事前にすべてわかっている**場合、操作を逆から処理することを考えます。

このテクニックは、次のような問題にも使えます。

- 道路を順番に封鎖したとき、連結成分の個数を求める。
- 頂点を順番に削除したとき、残ったグラフの連結性を調べる。
- 辺を順番に削除したとき、特定の2頂点がまだ連結か判定する。

頂点削除の問題でも、逆順に頂点を有効化し、その頂点とすでに有効な隣接頂点を Union-Find で統合すればよいことがあります。

ただし、追加と削除が任意の順番で混在する問題では、単純な逆順処理だけでは解決できません。その場合は、セグメント木と Rollback Union-Find を組み合わせるなど、より一般的なオフライン動的連結性の手法が候補になります。

### 典型②：複数の特殊頂点を1つに縮約する

本問では、発電所が何個あっても、知りたいことは「少なくとも1つに到達できるか」だけでした。

このように、複数の頂点が同じ役割を持ち、個々を区別する必要がないときは、それらを1つの頂点にまとめられる場合があります。

例えば、複数のゴールのうちどれかに到達できればよい問題で、仮想的なスーパーノードを使う方法があります。

ただし、縮約によって本来は連結でない頂点が連結になることには注意が必要です。

本問では、縮約後の連結性そのものを問うのではなく、「発電所のいずれかに到達できるか」だけを問うため、この変換が成立します。

発電所ごとに異なる属性があったり、どの発電所に繋がっているかを答える必要があったりするなら、このような縮約は一般にはできません。

### 典型③：管理する情報を減らせないか考える

Union-Find に連結成分ごとの情報を追加する方法は汎用的です。

本問でも、都市数と発電所の有無を各成分に持たせれば解けます。

しかし、特別な頂点を1つにまとめることで、答えを単なる連結成分のサイズに帰着できました。

これは、データ構造を複雑にする前に、**問題そのものを変形して、標準的なデータ構造だけで解けないか**考えることの重要性を示しています。

## 7\. 復習で押さえておきたいこと

- グラフの連結成分に関する問題では、まず Union-Find を候補に挙げる。
- 辺の削除が問題になるなら、操作を逆順にすることで追加に変えられないか考える。
- 逆順処理では、元の問題のどの時点に対応しているかを確認し、答えを記録するタイミングを間違えない。
- 複数の特殊頂点のうち「どれか1つ」でよいなら、それらを縮約できないか考える。
- 連結成分ごとの追加情報が必要に見えても、グラフの変換によって `size()` だけで済む可能性を検討する。

この問題では、**逆順処理に気づくことがアルゴリズム上の核心で、発電所の縮約に気づくことが実装を簡潔にする核心**です。

どちらも他のグラフ問題で再利用する価値の高い考え方です。
