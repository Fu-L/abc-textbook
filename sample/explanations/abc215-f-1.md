# ABC215 F - Dist Max 2 解説

(ABC F / 500点) (二分探索) (尺取り法) (ソート・最小値と最大値の管理)

この問題の核心は、**2点の距離の最大化を、距離が \(K\) 以上の2点が存在するかという判定問題に変換すること**です。

判定問題にすると、2次元の点の組み合わせを直接調べる必要がなくなり、ソートと尺取り法によって高速に解けます。

## 1\. 問題の整理

2次元平面上に \(N\) 個の点があり、2点 \(i,j\) の距離が

\[
d(i,j)=\min(|x_i-x_j|,\ |y_i-y_j|)
\]

と定義されています。

この距離の最大値

\[
\boxed{\max_{i\ne j}d(i,j)}
\]

を求めます。

制約は \(N\le 2\times10^5\)、座標は \(0\) 以上 \(10^9\) 以下です。全点対を調べる \(O(N^2)\) は間に合いません。citeturn140662search0turn140662search2

ここで重要なのは、距離の定義がユークリッド距離ではなく、**2つの座標差の小さい方**であることです。

例えば、2点 \(A=(0,0),B=(10,2)\) の距離は \(2\) ですが、\(C=(7,8)\) との距離は \(7\) になります。

つまり、一方の座標だけ大きく離れていても意味がなく、両方の座標で十分に離れた2点を探す必要があります。

## 2\. 距離の最大化を判定問題に変える

最大値を直接求めるのは難しそうなので、まず次の問題を考えます。

> 距離が \(K\) 以上の異なる2点が存在するか？

これは

\[
\min(|x_i-x_j|,|y_i-y_j|)\ge K
\]

を満たす点対が存在するか、という判定です。

最小値が \(K\) 以上になるためには、両方の値が \(K\) 以上でなければいけません。したがって、

\[
\boxed{
\begin{aligned}
|x_i-x_j|&\ge K\\
|y_i-y_j|&\ge K
\end{aligned}
}
\]

を同時に満たす2点を探せばよいことになります。

この変換によって、扱いにくかった `min` が2つの独立した条件になりました。

さらに、この判定には単調性があります。距離が \(K\) 以上の点対が存在するなら、それより小さい \(K\) でも必ず存在します。

答えが6の場合の判定結果

判定が Yes から No に変わる境界が答えです。

したがって、各 \(K\) に対する判定が高速にできれば、**答えで二分探索**できます。

残る課題は、判定を \(O(N^2)\) より十分高速にすることです。

## 3\. \(x\) 座標でソートすると何が変わるか

2つの絶対値を同時に扱うのは面倒です。そこで、まず点を \(x\) 座標の昇順にソートします。

ソート後の点を

\[
(x_0,y_0),(x_1,y_1),\ldots,(x_{N-1},y_{N-1})
\]

とすると、\(j< i\) について \(x_j\le x_i\) が成り立ちます。

これにより、

\[
|x_i-x_j|\ge K
\iff
x_j\le x_i-K
\]

と書けます。

つまり、各点 \(i\) を右側の点として固定すると、相手になれるのは

\[
\boxed{x_j\le x_i-K}
\]

を満たす左側の点だけです。

### 小さな例で考える

次の4点を考え、\(K=5\) が達成可能かを調べます。

点 D=(6,8) に対して、K=5 のとき x≤1 の点 A, B が候補です。点 C は x 座標が近すぎるため候補になりません。

具体的には、

| 点 | 座標 | Dとの \(x\) 差 | 候補？ |
|--------|--------|--------|--------|
| A | \((0,2)\) | 6 | ○ |
| B | \((1,14)\) | 5 | ○ |
| C | \((3,1)\) | 3 | × |

となります。

ここで注目したいのは、**相手の候補が \(x\) 座標による prefix（先頭からの連続区間）になる**ことです。

点 \(i\) を左から右へ動かすと、\(x_i-K\) も増加するため、候補集合は増えることしかありません。

この性質から、尺取り法を使えることがわかります。

ただし、候補を効率よく列挙できても、各候補との \(y\) 座標の差を毎回調べるのではまだ遅くなります。

## 4\. 候補の \(y\) 座標は最小値と最大値だけ見ればよい

点 \(i\) を固定したときに調べたいのは、

\[
|y_i-y_j|\ge K
\]

となる候補点 \(j\) が存在するか、ということです。

絶対値を外すと、

\[
y_j\le y_i-K
\quad\text{または}\quad
y_j\ge y_i+K
\]

です。

つまり、候補点の \(y\) 座標が十分小さいか、十分大きければよいわけです。

ここで、候補点の \(y\) 座標の最小値と最大値を

\[
y_{\min}=\min_j y_j,\qquad
y_{\max}=\max_j y_j
\]

とします。

候補点の中に条件を満たすものが存在することと、

\[
\boxed{
y_i-y_{\min}\ge K
\quad\text{または}\quad
y_{\max}-y_i\ge K
}
\]

が成り立つことは同値です。

先ほどの例で、点 D=(6,8) を考えると、候補 A, B の \(y\) 座標はそれぞれ \(2,14\) です。

したがって、

\[
y_{\min}=2,\qquad y_{\max}=14
\]

であり、

\[
8-2=6\ge5
\]

なので、距離が5以上の2点が存在するとわかります。

重要なのは、候補点が2個でも10万個でも、**必要な情報は \(y_{\min}\) と \(y_{\max}\) の2つだけ**ということです。

## 5\. 尺取り法による \(O(N)\) 判定

これまでの観察を組み合わせると、次の方法が得られます。

点を \(x\) 座標でソートしておき、点 \(i\) を左から順に調べます。

ポインタ \(p\) を用意して、まだ追加していない点のうち

\[
x_p\le x_i-K
\]

を満たすものを順番に候補へ追加します。

候補に追加するたびに \(y_{\min}\)、\(y_{\max}\) を更新します。

そして点 \(i\) に対して

\[
y_i-y_{\min}\ge K
\quad\lor\quad
y_{\max}-y_i\ge K
\]

を調べ、成立すれば `true` を返します。

```cpp

auto check = [&](int k) -> bool {
    int p = 0;
    int min_y = INT_MAX;
    int max_y = INT_MIN;

    for (int i = 0; i < N; ++i) {
        while (p < i && points[i].first - points[p].first >= k) {
            min_y = min(min_y, points[p].second);
            max_y = max(max_y, points[p].second);
            ++p;
        }

        if (p > 0 &&
            (points[i].second - min_y >= k ||
             max_y - points[i].second >= k)) {
            return true;
        }
    }
    return false;
};
```

なぜこれが \(O(N)\) なのでしょうか。

内側に `while` があるため、一見すると \(O(N^2)\) に見えるかもしれません。

しかし、\(p\) は一度進んだら戻りません。判定処理全体を通して、各点は高々1回しか候補へ追加されません。

- 外側の `for` が合計 \(N\) 回
- 内側の `while` が合計高々 \(N\) 回

したがって、判定1回の計算量は \(O(N)\) です。

## 6\. 解法全体と C++23 実装

判定関数 `check(K)` が作れたので、最後に答えで二分探索します。

答えは \(0\) 以上 \(10^9\) 以下です。

`ok = 0` を達成可能な下界、`ng = 10^9+1` を達成不可能な上界として二分探索します。

```cpp

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    cin >> N;

    vector<pair<int, int>> points(N);
    for (auto& [x, y] : points) {
        cin >> x >> y;
    }

    sort(points.begin(), points.end());

    auto check = [&](int k) -> bool {
        int p = 0;
        int min_y = INT_MAX;
        int max_y = INT_MIN;

        for (int i = 0; i < N; ++i) {
            while (p < i &&
                   points[i].first - points[p].first >= k) {
                min_y = min(min_y, points[p].second);
                max_y = max(max_y, points[p].second);
                ++p;
            }

            if (p > 0 &&
                (points[i].second - min_y >= k ||
                 max_y - points[i].second >= k)) {
                return true;
            }
        }
        return false;
    };

    int ok = 0;
    int ng = 1'000'000'001;

    while (ng - ok > 1) {
        int mid = ok + (ng - ok) / 2;
        if (check(mid)) {
            ok = mid;
        } else {
            ng = mid;
        }
    }

    cout << ok << '\n';
}
```

### 正当性の確認

任意の異なる2点 \(i,j\) について、\(x_i\ge x_j\) となるように順序を選びます。

この点対の距離が \(K\) 以上なら、\(x_j\le x_i-K\) なので、点 \(i\) を調べる時点で点 \(j\) は必ず候補集合に含まれます。

また、\(|y_i-y_j|\ge K\) なので、候補全体の最小値か最大値の少なくとも一方が判定条件を満たします。よって、存在する点対を見逃しません。

逆に判定条件が成立した場合、候補集合の最小値または最大値を実現する点は \(x\) 座標でも \(K\) 以上離れています。したがって、実際に距離が \(K\) 以上の点対が存在します。

以上から `check(K)` は正しく、二分探索によって最大の \(K\) が求まります。

### 計算量

座標の上限を \(C=10^9\) とすると、

| 処理 | 計算量 |
|--------|--------|
| ソート | \(O(N\log N)\) |
| 判定1回 | \(O(N)\) |
| 二分探索 | \(O(\log C)\) 回 |

全体では

\[
\boxed{O(N\log N+N\log C)}
\]

となり、空間計算量は \(O(N)\) です。

## 7\. この問題から学べる典型

### 典型① 最小値の最大化 → 答えで二分探索

本問で最も重要なのがこの発想です。

一般に、

\[
\max_{\text{選択}}\min(f_1,f_2,\ldots,f_m)
\]

という問題を考えます。

直接最適化する代わりに、ある値 \(K\) を固定して、

\[
f_1\ge K,\ f_2\ge K,\ \ldots,\ f_m\ge K
\]

を同時に達成できるか考えます。

こうすると、最適化問題が実現可能性の判定問題になります。

この手法を思い出したいのは、特に以下のような問題です。

- 何かの「最小値」をできるだけ大きくしたい
- 最適値そのものを管理するのは難しい
- 閾値を固定すれば、条件が単純になる
- 閾値について Yes / No が単調になる

例えば「複数の作業者に仕事を分配し、最も少ない作業量を最大化する」「選んだ要素同士の最小距離を最大化する」なども同じ考え方が候補になります。

ただし、**答えで二分探索を思いついたこと自体は解法の完成ではありません。** 判定問題が元の最適化より本当に簡単になるかを確かめることが大切です。

本問では `min` が2つの不等式に分解されるため、非常に有効でした。

### 典型② ソートによって候補集合を単調にする

尺取り法の本質は、単に2つのポインタを動かすことではありません。

**調べる位置を進めたとき、候補集合が規則的に変化する構造を利用すること**です。

本問では、候補集合が

\[
S_i=\{j\mid j<i,\ x_j\le x_i-K\}
\]

でした。

\(x\) 座標の昇順で調べれば、\(S_i\) は先頭からの連続区間になり、\(i\) が増えるにつれて拡大するだけです。

このように、

1. 一方の変数でソートする
2. もう一方の条件を満たす範囲を考える
3. その範囲が単調に動くことを確認する

という流れは、2次元の点を扱う問題で頻出です。

さらに、集合が拡大するだけなら、今回の最小値・最大値のように追加処理だけで管理できる情報が活躍します。

一方、候補が追加だけでなく削除もされる場合、単純な変数での最小値・最大値管理では対応できません。その場合は単調キュー、multiset、セグメント木などを検討します。

つまり、尺取り法が使えるかどうかだけでなく、**候補集合の変化に対して必要な情報を効率よく更新できるか**まで考える必要があります。

### 典型③ 存在判定では極値だけで十分な場合がある

本問で候補集合から知りたいのは、

\[
\exists y\in S:\ |y-a|\ge K
\]

という条件です。

これは

\[
\min(S)\le a-K
\quad\lor\quad
\max(S)\ge a+K
\]

と同値です。

別の表現をすると、

\[
\max_{y\in S}|y-a|
=
\max(a-\min(S),\ \max(S)-a)
\]

です。

**絶対値による距離が十分大きい要素が存在するか**を調べる場合、候補全体を保持せず、最小値と最大値だけで十分だとわかります。

この知識は、区間内・集合内の要素とある値との最大差を調べる問題にも使えます。

逆に、距離が十分小さい要素が存在するかを調べたい場合は、最小値と最大値だけでは不十分です。例えば \(S=\{0,10\}\)、\(a=5\) のとき、両端の情報だけでは内部に \(5\) が存在するか判別できません。

その場合は、順序付き集合で近傍要素を探すなど、別の情報が必要になります。

存在判定では、**存在する要素そのものが必要なのか、それとも極値の情報だけで条件を判定できるのか**を考える習慣が有効です。

## 8\. 復習で定着させたいこと

- **min の最大化**を見たら、まず閾値 \(K\) 以上を実現できるかという判定問題を考える。
- 2次元の条件に絶対値が含まれる場合、一方の座標でソートして絶対値を外せないか試す。
- ソート後の候補集合が単調に拡大するなら、尺取り法による線形時間処理を検討する。
- 候補から十分離れた値の存在を判定するなら、最小値と最大値で十分な可能性がある。
- 尺取り法の計算量はループの入れ子ではなく、ポインタが全体で何回動くかで評価する。

この問題は、**答えで二分探索 → ソートによる条件整理 → 尺取り法 → 極値だけの管理**という、複数の基本的な考察をきれいにつなげた問題です。

特に「判定問題に変換した後、必要な候補集合と管理すべき情報を分離して考える」という視点は、より難しい問題でも役立ちます。
