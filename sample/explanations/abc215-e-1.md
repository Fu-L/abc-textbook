# ABC215 E - Chain Contestant 解説

(500点) (Bit DP) (計算量 O(NK2\^K))

問題：urlAtCoder ABC215 Ehttps://atcoder.jp/contests/abc215/tasks/abc215_e

## 1\. 問題の整理

長さ \(N\) の文字列 \(S\) が与えられます。ここから **空でない部分列**を選び、次の条件を満たす選び方の個数を求めます。

**同じ文字は、選んだ部分列の中で必ず一つの連続した区間にまとまっていなければならない。**

例えば、次のようになります。

| 選んだ部分列 | 判定 | 理由 |
|--------|--------|--------|
| `AABBC` | OK | 各文字が一つの塊 |
| `BAABB` | NG | `B` が二つの塊に分かれる |
| `ABCA` | NG | `A` が途中で再登場 |
| `ABC` | OK | 同じ文字は一度しか現れない |

元の文字列の中で隣り合っている必要はありません。あくまで、**選んだ位置を順番に並べたとき**に条件を満たせばよいです。

制約は \(N\le 1000\)、文字の種類数は \(K=10\) です。答えは \(998244353\) で割った余りを求めます。citeturn128106view0turn171653view0

## 2\. 解法に至る考察

### 2.1. 左から順番に選ぶかどうかを決める

まず、部分列を数える基本的な方法を考えます。

文字列を左から見て、各文字について

- 選ばない
- 選ぶ

という二択を繰り返せば、すべての部分列を列挙できます。

しかし、そのままでは \(O(2^N)\) 通りあり、\(N\le1000\) では不可能です。

そこで、過去の選び方を全部記録する代わりに、**今後の選択に必要な情報だけを状態として持つ DP** を考えます。

そのためには、次の文字を選べる条件を明らかにする必要があります。

### 2.2. 次の文字を追加できるのはどんなときか？

例えば、今までに選んだ部分列が `AABBC` だったとします。

ここに次の文字を追加するとどうなるでしょうか。

| 追加文字 | 結果 | 判定 |
|--------|--------|--------|
| `C` | `AABBCC` | OK |
| `D` | `AABBCD` | OK |
| `A` | `AABBCA` | NG |
| `B` | `AABBCB` | NG |

ここから、重要な性質が見つかります。

**追加する文字 \(x\) は、次のいずれかを満たせばよいです。**

1. 直前に選んだ文字も \(x\) である。
2. \(x\) を過去に一度も選んでいない。

一度別の文字に移ってしまったら、以前の文字に戻ることはできません。

つまり、過去の部分列の具体的な並びは必要なく、次の二つがわかれば追加可能か判断できます。

- 今までに使った文字の集合
- 最後に使った文字

これが DP の状態になります。

### 2.3. なぜ「使った文字の集合」だけでは足りないか？

ここは状態設計で重要なポイントです。

例えば、次の二つの部分列を考えます。

部分列 1

## A

## B

最後は B

部分列 2

## B

## A

最後は A

どちらも使った文字の集合は \(\{A,B\}\) です。

しかし、次に `A` が来た場合、

- `AB` に追加すると `ABA` となり不適切
- `BA` に追加すると `BAA` となり適切

です。

したがって、集合が同じでも最後の文字が異なれば、今後の選択肢が変わります。

このため、最後の文字も状態に含める必要があります。

### 2.4. 文字の種類数が小さいことを利用する

ここで制約を確認します。

\(N\) は最大 \(1000\) ですが、登場する文字は `A` から `J` までの **10 種類**しかありません。

使った文字の集合は、最大でも

\[
2^{10}=1024
\]

通りです。

さらに最後の文字は 10 通りなので、状態数は最大で

\[
1024\times10=10240
\]

通りしかありません。

つまり、集合を bitmask で管理すれば十分に高速な DP ができそうです。

これが本問の核心である **Bit DP** につながります。

## 3\. DP の設計

文字 `A` から `J` を整数 \(0\) から \(9\) に対応させます。

次の DP を定義します。

\[
\boxed{dp[i][mask][last]}
\]

これは、

- 先頭 \(i\) 文字までを処理した
- 少なくとも一つの文字を選んでいる
- 使った文字の集合が `mask`
- 最後に選んだ文字が `last`
- 条件を満たしている

ような選び方の個数です。

`mask` の \(x\) ビット目が立っていることは、文字 \(x\) をすでに使ったことを意味します。

### 遷移

次に処理する文字を \(x=S_i\) とします（ここでは \(S\) を 0-indexed とします）。

現在の状態を `dp[i][mask][last]` としたとき、次の選択ができます。

**ケース1：文字 \(x\) を選ばない**

常に可能で、状態は変化しません。

\[
dp[i+1][mask][last]
\mathrel{+}=dp[i][mask][last]
\]

**ケース2：文字 \(x\) を選ぶ**

さらに二つの場合に分かれます。

\(A) \(x=last\) の場合

現在の文字の塊を延長するだけなので、集合も最後の文字も変わりません。

\[
dp[i+1][mask][last]
\mathrel{+}=dp[i][mask][last]
\]

\(B) \(x\notin mask\) の場合

新しい文字の塊を開始できます。

\[
dp[i+1][mask\mid(1\ll x)][x]
\mathrel{+}=dp[i][mask][last]
\]

ここで \(\mid\) はビット OR です。

一方、\(x\) がすでに使われていて \(x\neq last\) なら、その文字に戻ることはできないため遷移しません。

**ケース3：文字 \(x\) から新しく部分列を開始する**

これまで何も選ばず、今回初めて文字を選ぶ場合です。

\[
dp[i+1][1\ll x][x]\mathrel{+}=1
\]

空の部分列を状態に持たない設計なので、この遷移を別に加えます。

## 4\. 小さい例で DP を追う

`S = ABA` を使って確認しましょう。

**処理する文字を進める** (/ 3 文字)

| 使用集合 | 最後 | 個数 | 対応する部分列 |
|--------|--------|--------|--------|

選び方の合計

[戻る]

最後の状態では、使用集合が \(\{A,B\}\) の部分列が `AB` と `BA` に分かれている点に注目してください。

両者は同じ集合を使っていますが、最後の文字が違うため別の状態になります。

`ABA` の非空部分列の選び方は全部で \(2^3-1=7\) 通りです。このうち3文字すべてを選ぶ `ABA` だけが不適切なので、答えは \(6\) です。

## 5\. C++23 実装

メモリを節約するため、DP の文字位置方向を rolling array で管理します。

```cpp

#include <bits/stdc++.h>
using namespace std;

constexpr int MOD = 998244353;
constexpr int K = 10;
constexpr int M = 1 << K;

void addmod(int& a, int b) {
    a += b;
    if (a >= MOD) a -= MOD;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N;
    string S;
    cin >> N >> S;

    vector<array<int, K>> dp(M), ndp(M);

    for (char c : S) {
        int x = c - 'A';
        int bit = 1 << x;

        for (auto& v : ndp) v.fill(0);

        // 今回の文字から部分列を始める
        addmod(ndp[bit][x], 1);

        for (int mask = 1; mask < M; ++mask) {
            for (int last = 0; last < K; ++last) {
                int ways = dp[mask][last];
                if (ways == 0) continue;

                // 今回の文字を選ばない
                addmod(ndp[mask][last], ways);

                if (last == x) {
                    // 現在の文字の塊を延長
                    addmod(ndp[mask][last], ways);
                } else if (!(mask & bit)) {
                    // 未使用の文字で新しい塊を開始
                    addmod(ndp[mask | bit][x], ways);
                }
            }
        }

        dp.swap(ndp);
    }

    int ans = 0;
    for (const auto& v : dp) {
        for (int ways : v) {
            addmod(ans, ways);
        }
    }

    cout << ans << '\n';
}
```

計算量は、各文字について最大 \(2^K K\) 個の状態を調べるので、

\[
\boxed{O(NK2^K)}
\]

です。

\(K=10\) なので、およそ \(1000\times1024\times10\)、約1000万状態の処理で済みます。

空間計算量は、rolling array により

\[
\boxed{O(K2^K)}
\]

です。

### 正しさの要点

左から順番に文字を処理すると、条件を満たす部分列に対して、各文字を選んだかどうかが一意に決まります。

すでに始めた部分列に文字を追加する際、その文字が直前と同じか未使用なら、どの文字も一つの塊になるという条件が保たれます。逆に、以前使った文字を別の塊として追加すると条件を破ります。

DP はこの選択を過不足なく列挙しているため、最終的な全状態の和が求める答えになります。

## 6\. この問題から学ぶ典型

### 典型①：種類数が小さいなら「使用済み集合」を bitmask にする

本問では \(N\le1000\) ですが、使われる文字の種類数は \(K=10\) しかありません。

重要なのは、入力全体の大きさではなく、**記録したい情報が何通りあるか**です。

各種類について「使った／使っていない」という2値の情報で十分なら、集合全体は \(2^K\) 通りしかありません。

一般に、対象の種類が少なく、過去の使用状況によって今後の操作が制約される場合は、

\[
dp[mask][\text{その他の状態}]
\]

という設計を検討できます。

代表例には、巡回セールスマン問題の Bit DP があります。ただし、そちらは「各都市を一度ずつ訪問する」問題であり、本問では「一つの文字を連続して何度も選べる」点が異なります。

**Bit DP を連想する手がかりは「集合を扱う」という言葉そのものではなく、各要素について必要な履歴が少数の状態に圧縮でき、要素数 \(K\) が小さいこと**です。

### 典型②：今後の選択肢が同じ履歴をまとめる

DP の状態設計で使える、より一般的な考え方です。

過去の選択列が異なっていても、今後できる選択と、その結果得られる状態が同じなら、それらを一つにまとめて個数だけ管理できます。

本問であれば、例えば

- `AABB`
- `ABB`
- `AB`

は、いずれも使用集合が \(\{A,B\}\) で最後の文字が `B` です。

これらの部分列に対して、今後どの文字を選べるかという規則は完全に一致しています。

したがって、選んだ文字列そのものを持つ必要はありません。

一方、`AB` と `BA` は最後の文字が違うため、今後の選択肢が異なります。よって同じ状態にまとめられません。

これは DP の状態を設計する際に繰り返し使える視点です。

> 過去の履歴をすべて保存するのではなく、「これ以降の処理を正しく決めるために、過去から何を覚えておく必要があるか」を考える。

この視点は、桁 DP、文字列 DP、グラフ上の状態 DP などにも共通しています。

### 典型③：同じ種類が再登場できない条件を管理する

本問の条件は、別の形で言い換えることができます。

**一つの種類の使用を終了したら、二度とその種類に戻れない。**

選んだ文字列を同じ文字ごとの塊に圧縮すると、例えば

\[
\texttt{AAABBBCCAAA}
\longrightarrow
\texttt{ABCA}
\]

となります。

本問では、この圧縮後の列に同じ文字が2回登場してはいけません。

この構造を一般化すると、

- 使い終わった種類に戻れない
- 今使っている種類だけは継続できる
- 未使用の種類に切り替えられる

という遷移規則になります。

同じ色の作業を一つの連続区間で処理する問題や、一度離れたカテゴリに戻れない操作列を数える問題などでも有効なモデルです。

このとき、管理すべき情報は「すでに登場した種類」と「現在の種類」になります。

さらに、本問では各文字が独立に選択可能なので、同じ文字を再び選ぶ場合には現在の状態から「選ぶ」「選ばない」の両方が成立します。その結果、同じ状態に2通りの遷移が加わることにも注意が必要です。

## 7\. 復習で定着させたいこと

- **制約の小さい次元を探す。** \(N\) が大きくても、種類数 \(K\) が小さければ \(2^K\) の状態管理が候補になる。
- **DP の状態は未来への影響から決める。** 過去の文字列すべてではなく、使用集合と最後の文字だけを残せばよい。
- **一度使った種類に戻れない条件を見抜く。** 「各種類が一つの連続区間になる」は「使用済みで現在と異なる種類は選べない」と言い換えられる。
- **空の状態の扱いに注意する。** 今回の実装では最初の文字を選ぶ遷移を別に設けている。
- **同じ状態への複数の遷移を数え落とさない。** 同じ文字が続く場合、選ぶ場合と選ばない場合は異なる選び方になる。

本問で特に重要なのは、Bit DP 自体よりも、**「使用済み集合」と「現在の種類」だけで、すべての過去の選択履歴を要約できると見抜くこと**です。

この状態設計の感覚が身につくと、種類数が小さい数え上げ問題に対して、自然に Bit DP を組み立てられるようになります。
