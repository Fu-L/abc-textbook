# PR #65 G・H・Exレビューの補修

対象: [Gレビュー](https://github.com/Fu-L/abc-textbook/pull/65#pullrequestreview-5406689669)と
[H・Exレビュー](https://github.com/Fu-L/abc-textbook/pull/65#pullrequestreview-5406798747)。Blocker
3件、Medium 12件、Lowの全提案を扱い、35記事を修正した。

根本原因は、帰着した後の量を元の出力へ戻していないこと、等式の整合性と非負解の存在を混同したこと、手順を技法名だけで済ませたことだった。以下では初期値・遷移・終了条件・出力の接続を具体化し、既に述べた理由の再掲を減らした。長い一般証明を追加するのでなく、手順を再現するための式や小例を考察に置いた。

ABC323-Gでは、関連典型から推定する前提と、採用した解法の実際の前提を混同していた。既存のauthoring
unitが持つ前提一覧を再生成時にも尊重し、新規執筆時は明示された一覧があれば使い、指定がなければ従来の推定を使う。問題専用の条件分岐は追加していない。本文・Claim・入力packet・検査記録・私用プレビューを35
shardで同期した。

今後の補修でも、まず「何を状態にしたか」から「問題が何を出力するか」までを一度つなぎ、負値・空状態・最後の操作など帰着で変わる境界を確認する。共通手法は前提単元へ任せ、固有の添字や係数は省略しない。考察は発見と具体的手順、正当性は対応や不変量へ役割を分ける。

## 有限検算

追加した `pr65-review19-mathematical-checks.py` はPython
3.9以上、追加依存なし、乱数なし。CIから実行する。

- ABC254-G: 3ビル・4階・2エレベーターの22,032問い合わせで、元の階移動と通路の最短路に比較。

- ABC464-G: N=2..8の全508文字列で、費用曲線を予算別へ戻した結果と全flip集合を比較。
- ABC386-G: N=2..4,M=1..3の9設定で、全辺重み割当のKruskal総和に比較。
- ABC238-Ex: N=2..6の全124方向列で、前向きの有理数期待値に比較。
- ABC399-G: 小行列の全65,610 suffix判定で、生成位置付き基底と作り直した消去のrankに比較。
- ABC448-G: 三角形上の入れ子最大化を、有理数による頂点全列挙と6設定で比較。公式入力例1のBAN後の値から29/55を確認。
- ABC252-Ex: 重複を含む左右多重集合の5,184順位を、XORペア全列挙sortと比較。
- ABC280-Ex: 二進文字列から作る930設定で、同一suffixと葉の終端を含む全substring出現のsortに比較。
- ABC296-Ex: 1×1、1×4、2×3、3×3の全590必須黒配置で、全塗り集合の連結判定に比較。
- ABC273-Ex: 初期端点を含む2,145位置列で、明示的な祖先操作集合に比較。
- ABC397-G: 小さいlabelの全組でcut方向・費用・二段禁止を確認。ABC281-Exの0/1材料とABC365-Gの区間内部の出入りも確認。

既存の数学検算18本も維持し、ABC382-Gの座標正規化と距離表、全868本文とClaimの整合性を含めて再実行する。有限検算は本文の一般の説明を支える境界確認であり、全問の独立AC検証を行ったという意味ではない。
