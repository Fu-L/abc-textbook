# コード・数式・表の横幅

[Issue #111](https://github.com/Fu-L/abc-textbook/issues/111)の表示変更。確認日: 2026-10-17。
[文字組み](typography.md)と[静的な数式表示](update-manual.md#数式とコードの記法)を引き継ぐ。

## 表示の選択

- コード・擬似コードは`white-space: pre`で原稿の改行と字下げを保つ。長い行はコード枠内で横スクロールする。Tabは4文字分として表示し、文字そのものは保持する。
- 文章中の識別子は通常の本文と一緒に折り返す。折り返すための文字や改行を原稿・DOMへ挿入しない。
- 数式は式の途中で切らず、幅を超える場合だけ局所スクロールする。短いインライン数式は文章中に収まり、長い式もページ全体を押し広げない。
- 表は日本語をセル内で折り返し、長い識別子を一文字ずつ縦に並べない。必要な幅は表の枠内で横スクロールする。`table`・見出し・行・セルはそのまま保持する。

各枠はTabで移動でき、左右矢印キーで続きを読み、次のTabで抜けられる。フォーカスには既存の輪郭線を使う。JSやコピー機能、依存パッケージは追加しない。

390px幅の検証原稿では、変更前はページの横幅が745pxになった。変更後は390pxに収まり、コード枠の表示幅364pxに対して内容1241px、表の表示幅366pxに対して内容1439pxをそれぞれ枠内で読める。自動折り返しがなくなり、C++断片の高さは479pxから269px、擬似コードは321pxから111pxへ変わった。数値はこの原稿・環境の観測であり、可読性の点数ではない。

トレードオフとして、長いコード行や表の離れた列を見るときは横操作が必要になる。ABC251
Fでも長い日本語を含む擬似コードは同じ扱いになる。通常の文章・短い表・短い式は幅内で読める。枠は短い場合にもTabの停止点となるが、幅測定のためのブラウザー用JSは増やさない。横操作を減らすには執筆時に意味のまとまりで改行し、長い数式を独立させる。表示改善のために既存原稿へ機械的な改行を加えない。

## 確認範囲

- Node
  24.18.0で型検査、rendererの文字保持と構造のunit検査、公開projectionの互換検査、本番subpathのbuild・内部リンク検査。
- Chromiumで既存の文字組み・数式・320 / 390 /
  720pxの代表ページreflowを確認。代表単元・長い単元・ABC391 F・ABC251 F・コンテスト表を含む。
- 検証原稿はChromium / Firefox / WebKitの320 / 390 / 720 /
  1440px、明暗両配色、JS無効で確認。Tab・矢印キーによる各枠の操作、表の見出し構造、コード文字列・改行・Tabの保持を検査する。数式フォントの幅はbrowser間で異なり、PCで収まる式もスマホではスクロールする。
- Chromiumの設定画面で実際に200%ズームし、1440pxウィンドウが720 CSS px・devicePixelRatio
  2になることを確認。上記の単元・問題に加えてABC290
  Exの表と検証原稿で、ページ全体の横あふれがなく、各枠を矢印キーでスクロールできた。

Codexによる表示・操作確認であり、実機スマホや読者の学習効率の測定は未実施。問題・単元のID、分類、本文、URL・anchor、学習記録の形式は変更していない。
